# Sprint 164：YouTube Oddlyhuman 单频道完整拆解

## 状态

Completed

## Goal

以 LuluJAI 第 41–60 条新增频道 Oddlyhuman 为第一个单频道对象，对其当前全部 9 条 YouTube 公热视频
建立可复核拆解卡；分别分析选题、标题承诺、缩略图视觉、时长、发布节奏和频道内表现分布，判断哪些是
可迁移的内容设计，哪些只是拥挤模板或不可证实推断，并建立后续逐频道复用的统一模板。

## In Scope

- 从已验证 YouTube 官方频道 ID 与 RSS 确认 Oddlyhuman 当前公开视频边界和发布顺序。
- 对全部 9 条使用 YouTube 官方 oEmbed / 公共视频页复核标题、视频 ID、发布日期、时长、当前播放、
  非直播状态与官方缩略图；记录统一观察时间。
- 临时读取 9 张官方缩略图做人工视觉分析，不把图片或视频下载物提交到仓库。
- 对每条统一标记问题类别、标题主体、承诺结构、具体性、视觉主体、文字量、构图、色彩与风险。
- 描述频道内播放分布、前 3 / 后 3 与发布时间的关系；明确样本只有 9 条，不能做因果归因。
- 建立可复用频道拆解模板，输出“可借鉴 / 不应复制 / 需要实验验证”的分层设计。
- 更新 YouTube 研究索引、持续研究日志和项目进度。

## Out of Scope

- 不继续翻 LuluJAI 榜单，不研究 Pastly 或其他频道；它们留给后续独立 Sprint。
- 不观看或下载完整视频，不读取字幕、脚本、评论、频道后台、流量来源、留存、CTR、收入或制作成本。
- 不把 YouTube 视频当作历史事实来源，不复刻标题、缩略图、脚本、画面、音乐或频道身份。
- 不从播放量推断单一标题、题材或缩略图导致表现，不承诺增长、获利或可复制推荐。
- 不创建脚本、分镜、媒体、发布实验、定时任务或自动采集实现。
- 不修改六题排序、默认视频长度、`strategy_memory.md`、Skill、业务代码、数据库或前端。

## Done Means

- 官方 RSS 与视频页共同证明当前窗口覆盖 9/9 条，视频 ID 唯一，字段无缺失。
- 9 条均完成统一标题与缩略图分类，且观察与推断明确分开。
- 播放分布包含总量、中位数、前 3、后 3、发布日期 / 视频年龄边界，不用当前播放计算增长速度。
- 至少记录 3 个可借鉴机制、3 个不应复制模式和 3 个后续可验证假设；这些都不升级长期规则。
- 频道拆解模板可以让下一个频道使用相同字段，不为 Oddlyhuman 单独定制口径。
- 仓库不包含缩略图副本、视频、凭据、会话、私有响应或发布任务。
- 控制器校验、本地 Markdown 链接、敏感字符串扫描、9 条计数和 `git diff --check` 通过。

## Outcome

- YouTube 官方 RSS 与 9 个公开视频页共同确认当前频道窗口为 9/9 条；字段完整、ID 唯一、均非直播，
  9 张官方缩略图均为 1280×720，且只在临时目录用于人工观察。
- 9 条当前播放合计 603,352；严寒视频单条 582,236，占 96.5%，是中位数的 217.4 倍；去掉异常后
  其余 8 条平均 2,639.5，不能把频道均值或单条异常写成稳定机制。
- 视觉系统稳定为粗轮廓卡通、2–4 个大写词与单问题场景；异常视频独有猛犸剖面视觉谜题，但史实暗示
  风险高。两张缩略图还内含与真实时长不一致的 `25:10` 标记。
- 描述来源从早期无引用逐步提升到最新 3 条有 4 / 8 / 11 个直接链接；这改善可审计性，但没有证据证明
  会提高播放。下一轮按同一模板拆解 Pastly。
