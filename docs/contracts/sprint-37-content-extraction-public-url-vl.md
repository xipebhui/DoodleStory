# Sprint 37 合同：内容提取公网 URL 视觉理解

## 目标

优化内容提取下载素材后的处理路径：下载素材保存为 DoodleStory 资产时保留原始文件内容，并并行上传对象存储；图文图片理解阶段按原顺序提交对象存储公网原图 URL，不再把图片转成 base64 data URL。

## 范围内

- 下载素材登记资产时继续使用原始文件 bytes，不做压缩、缩放或格式转换。
- 下载得到的图片和 metadata 资产保存/对象存储上传改为并行执行。
- 并行上传完成后仍按下载返回顺序写入 `ContentExtractionMedia.display_order`。
- 图文 VL 请求按顺序传 `image_url.url = asset.public_url`。
- 图片理解阶段如果图片没有公网 HTTP(S) URL，明确失败。
- 增加单元测试覆盖公网 URL 提交和并行上传顺序。

## 范围外

- 不改变抖音下载服务本身。
- 不改变视频音频转写流程。
- 不新增 base64 fallback。
- 不拆分为逐页 VL 请求。

## 完成标准

- 新的图文内容提取请求日志中不再出现 `data:image/...;base64` 图片内容。
- VL 请求的图片 URL 与数据库资产 `public_url` 一致，并保持图片顺序。
- 上传阶段可以并行完成，但数据库展示顺序不变。
- `./scripts/check.sh` 通过。

## 风险 / 说明

- VL 服务必须能访问对象存储公网 URL；如果本地或环境未配置公网对象存储，内容提取会明确失败。
- 一次提交多张公网原图仍可能受 VL 模型处理速度影响，但请求体会显著小于 base64 方案。
