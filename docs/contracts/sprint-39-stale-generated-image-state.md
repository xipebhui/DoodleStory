# Sprint 39 合同：旧图片生成状态不污染任务详情

## 目标

修复任务已经完成但详情页仍显示分镜生成中的问题。任务重试后，上一轮中断留下的旧 `queued` / `running` 图片版本不应覆盖当前成功图，也不应让前端持续轮询或阻止单 panel 修改。

## 范围内

- 后端任务重试时，将上一轮仍处于 `queued` / `running` 的图片生成版本明确标记为 `failed`。
- 旧运行中图片版本写入明确错误码和错误文案，表示已被重新生成取代。
- 前端详情页选择 panel 展示图时，只有任务本身仍在运行，或当前存在用户单 panel 修改时，才让 `queued` / `running` 图片覆盖当前图。
- 前端轮询判断只把用户单 panel 修改中的图片视作已完成任务后的活跃工作。
- 增加单元测试覆盖旧运行中图片版本的作废逻辑。

## 范围外

- 不改变图片 Provider 请求流程。
- 不自动重跑旧图片版本。
- 不调整任务下载规则。

## 完成标准

- 远程任务 `43a48af4739f4e0791965ba06070d12f` 详情展示当前成功图片，不再被旧 running 版本覆盖。
- 已完成任务里遗留的旧 running 图片不会导致详情页持续显示生成中。

- 单 panel 修改仍会在生成期间覆盖当前 panel 展示为生成中，因为这是用户正在进行的真实修改。
- 旧 running 版本标记失败仅表示该版本被后续重试取代，不代表当前任务失败。
