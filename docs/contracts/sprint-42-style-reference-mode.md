# Sprint 42 合同：风格参考方式可选择 Prompt 或参考图

## 目标

让风格支持两种参考方式：使用 `style_prompt` 作为生图风格参考，或使用风格参考图作为生图模型输入参考。任务生成、单 panel 修改和风格测试必须使用同一套风格参考策略，避免测试结果和正式任务不一致。

## 范围内

- 风格新增参考方式字段：`prompt` 和 `image`。
- 旧风格、旧任务、旧风格测试默认保持 `prompt` 模式，现有行为不改变。
- 任务创建和重试时保存风格参考方式快照。
- `image` 模式下，任务创建和重试时保存当时风格参考图的任务级快照。
- 正式 panel 生图和单 panel 修改复用现有 Provider 参考图 URL 通道传入风格参考图。
- 人物参考图和风格参考图同时存在时，按固定顺序合并：人物参考图在前，风格参考图在后。
- 风格测试按风格参考方式决定是否传入风格参考图。
- 前端风格表单展示并保存参考方式，风格列表和测试页展示当前策略。
- 更新产品规格和进度记录。

## 范围外

- 不新增自动选图、裁剪、打分、排序或智能挑选参考图。
- 不在不同 Provider 之间做失败兜底或降级。
- 不把本地非公网图片自动转存为公网地址。
- 不改变人物参考图生成自身的输入方式。
- 不调整图片模型白名单或 Provider 真实远端配置。

## 完成标准

- 旧数据迁移后默认为 `prompt` 模式。
- `prompt` 模式下，最终生图 prompt 继续包含 `style_prompt_snapshot`，Provider 参考图只包含人物参考图。
- `image` 模式下，最终生图 prompt 不再拼接大段 `style_prompt_snapshot` 作为风格来源，Provider 参考图包含任务快照中的风格参考图。
- 风格测试在 `image` 模式下传入风格参考图；没有可用公网参考图时明确失败。
- 后端单元测试覆盖两种参考方式和参考图合并顺序。
- `./scripts/check.sh` 通过，或明确记录未通过原因。

## 风险 / 说明

- 当前 QY Gateway 的参考图数量有限；当人物参考图和风格参考图合计超过模型限制时，任务会明确失败，不静默丢弃参考图。
- 参考图模式要求参考图有公网 HTTP(S) URL；本地相对资产 URL 不会被自动作为 Provider 输入。
