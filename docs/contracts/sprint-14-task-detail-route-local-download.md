# Sprint 14 合同：任务详情稳定 URL 与本地打包下载

## 目标

任务详情打开后，浏览器地址必须携带任务 ID，避免刷新、前进后退或列表刷新时跳到其它任务；批量下载图片必须从本地已有资产文件打包，下载按钮需要显示处理中状态并阻止重复点击。

## 范围内

- 前端任务详情 URL：
  - 任务列表仍为 `/tasks`。
  - 打开任务详情时地址变为 `/tasks/{task_id}`。
  - 直接访问或刷新 `/tasks/{task_id}` 时加载对应任务详情。
  - 关闭详情时回到 `/tasks`。
- 前端下载交互：
  - 点击“下载图片”后显示打包中状态。
  - 打包请求未完成前禁用按钮，防止重复提交。
  - 打包失败时展示后端返回的明确错误。
- 后端任务下载打包：
  - 本地资产直接从本地文件读取。
  - 七牛资产优先使用与 `storage_key` 对应的本地镜像或已有本地缓存。
  - 任务下载打包不得为了 zip 生成从公开 CDN 回源下载图片。
  - 生成的 zip 下载包保存为本地资产，由后端本地文件响应下载。
  - 新写入七牛的资产同时保留本地镜像，供后续本地处理和打包使用。
- 更新规格和进度记录。

## 范围外

- 不引入独立下载服务、外部队列或后台异步 zip 状态机。
- 不迁移历史七牛资产。
- 不改变图片预览仍可直接使用公开 CDN URL 的策略。
- 不改变任务列表分页、筛选和生成流程。

## 完成标准

- 点击任务行后浏览器地址包含任务 ID。
- 刷新 `/tasks/{task_id}` 后仍打开该任务详情。
- 点击详情关闭按钮后地址回到 `/tasks`。
- 下载按钮在打包期间显示忙碌态且不能重复点击。
- 任务下载 zip 只读取本地已有文件；缺少本地文件时返回明确失败信息。
- 任务下载 zip 本身保存为本地资产，不上传到七牛后再让浏览器回源下载。
- `npm run build`、`backend/.venv/bin/python -m compileall backend/app` 和 `./scripts/check.sh` 通过。

## 验证

自动验证：

```bash
npm run build
backend/.venv/bin/python -m compileall backend/app
./scripts/check.sh
```

功能验证：

1. 本地打开 `/tasks`，点击任一任务行，确认地址变为 `/tasks/{task_id}`。
2. 刷新 `/tasks/{task_id}`，确认详情仍是同一个任务。
3. 点击关闭详情，确认地址回到 `/tasks`。
4. 点击“下载图片”，确认按钮显示打包中并被禁用。
