# Sprint 38 合同：内容提取卡死状态恢复

## 目标

修复内容提取任务在后端进程重启或中断后长期停留 `processing` 的问题。因为内容提取当前使用 FastAPI 同进程后台任务，进程重启后无法继续旧任务，所以启动时必须把遗留运行中记录明确标记为失败。

## 范围内

- 后端启动时扫描 `content_extractions.processing_status = processing` 的历史记录。
- 将这些遗留记录标记为 `failed`，并写入清晰的失败原因。
- 增加日志记录恢复数量和对应内容提取 ID。
- 增加单元测试覆盖遗留运行中记录的状态收尾逻辑。
- 更新产品规格和进度记录。

## 范围外

- 不引入外部队列或复杂状态机。
- 不自动重跑内容提取任务。
- 不对图片生成任务状态恢复做额外改造。

## 完成标准

- 服务重启后不会继续展示上一个进程遗留的内容提取 `processing` 状态。
- 被中断的内容提取任务显示明确失败原因，用户可重新发起提取。
- 指定远程任务 `61d7a0ce7f9b43239fa560f50447c73d` 被标记为失败。
- `./scripts/check.sh` 通过。

## 风险 / 说明

- 这是对同进程后台任务不可跨进程恢复的显式收尾，不是兜底重试。
- 如果后续内容提取改为持久队列，应重新设计运行中任务的恢复语义。
