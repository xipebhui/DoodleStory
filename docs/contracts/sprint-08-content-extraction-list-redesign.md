# Sprint 08 合同：内容提取列表化与故事总结

## 目标

将 `内容提取` tab 从当前的一页式工作台重构为任务列表入口，并新增图文故事总结步骤。用户通过创建弹窗提交抖音分享文本，通过详情弹窗查看下载媒体、原始文案和故事总结。

## 范围内

- 前端 UI 重构：
  - `内容提取` tab 首屏改为内容提取任务列表。
  - 创建内容提取任务改为弹窗。
  - 查看内容提取详情改为弹窗。
  - 详情弹窗内展示 `文案`、`故事总结`、`媒体` 三个区域或 tabs。
  - 保留图片点击放大预览。
- 列表性能边界：
  - 列表页只请求摘要接口。
  - 列表页不加载完整 `media` 数组，不加载所有图片。
  - 点击列表行后才请求详情。
- 新增图文故事总结：
  - 对图文作品，按图片 `display_order` 顺序输入全部图片。
  - 输出并保存 `故事内容`、`故事爆点`、`目标观众`。
  - 详情弹窗支持 `总结故事` 和 `重新总结故事`。
- 后端 API 和数据：
  - 内容提取摘要增加故事总结相关预览和状态字段。
  - 内容提取详情增加完整故事总结字段。
  - 新增故事总结同步接口。
  - 普通用户只能访问自己的故事总结动作和结果，Admin 可访问全部。
- 文档：
  - 以 `docs/design/content-extraction-list-redesign.md` 作为 UI 和交互设计来源。
  - 更新 `docs/progress.md` 的实施和验证记录。

## 范围外

- 不引入异步状态机、worker、队列、轮询或取消流程。
- 不让前端直连 `127.0.0.1:8010`。
- 不把下载服务返回的服务器绝对路径暴露给浏览器。
- 不让列表接口返回所有图片或完整媒体数组。
- 不为视频故事总结设计隐式兜底；视频故事总结需要另行设计视频帧或视频理解路径。
- 不自动把提取文案或故事总结创建为 DoodleStory 生成任务。
- 不自动总结、润色或改写 `提取文案` 的原始文案结果。
- 不做 Mock 故事总结结果。

## 完成标准

- `内容提取` tab 首屏是列表页，有搜索、筛选、分页、空状态、错误状态和 `新建提取` 主操作。
- 创建弹窗能完成 `解析并下载`，失败保留输入，成功后刷新列表并打开详情弹窗。
- 列表接口和前端列表渲染不加载所有图片。
- 详情弹窗按需加载完整内容提取记录。
- 图文记录可以执行 `总结故事`，并展示故事内容、故事爆点和目标观众。
- 视频记录默认不启用图文故事总结入口，并显示明确说明。
- 已运行 `./scripts/check.sh`。
- 使用真实图文链接完成至少一次浏览器验证：下载、打开详情、提取文案、总结故事、关闭弹窗后列表状态仍保留。

## 验证

自动验证：

```bash
./scripts/check.sh
```

人工验证：

1. 打开 `内容提取` tab，确认首屏只展示列表和 `新建提取`。
2. 检查 Network：列表请求只调用摘要接口，不请求详情，不加载所有图片。
3. 点击 `新建提取`，粘贴完整抖音分享文本并下载。
4. 下载成功后自动打开详情弹窗。
5. 在详情弹窗中点击 `提取文案`，确认原始文案展示正常。
6. 点击 `总结故事`，确认输出 `故事内容`、`故事爆点`、`目标观众`。
7. 关闭详情弹窗，确认列表保留筛选和分页状态。

## 交接
