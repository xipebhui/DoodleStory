# Sprint 52 合同：抖音账号与评论多维分析策略

## 目标

把抖音热门样本 Skill 从“基础数据获取”扩展到下一步分析契约：对候选作品背后的账号主页、评论区、开头结尾 VL 证据，以及文案和热门讨论的关系做结构化沉淀，方便后续脚本和 Skill 自动迭代选题方向。

## 范围内

- 将现有关键词搜索、筛选、下载和基础指标采集明确命名为“基础数据获取”。
- 补充账号主页多维分析策略：作品数量、近期更新、流量稳定性、爆款是否偶发、图文占比和选题集中度。
- 补充评论区分析策略：高赞评论、高回复评论、讨论触发点、用户补充故事、争议和求后续信号。
- 补充 VL 开头和结尾点检策略，尤其标记最后一张图是否为实景、真人、截图或证据型图片。
- 补充文案与评论区热门讨论的合并分类字段，说明这些分类如何反哺后续关键词、评分权重和选题迭代。
- 更新 `docs/progress.md`。

## 范围外

- 不在本 sprint 内实现新的账号分析脚本。
- 不在本 sprint 内实现评论聚类脚本。
- 不修改 DoodleStory 后端内容提取链路。
- 不引入新的 VL 模型或替换现有内容提取 VL 路径。
- 不默认批量抓取账号全量评论。

## 完成标准

- Skill 主流程能清楚区分“基础数据获取”和“账号与评论多维分析”。
- 字段表覆盖账号主页、评论区、开头/结尾 VL、文案评论合并沉淀和下一轮迭代假设。
- 策略文档说明每类分析为什么做、看什么证据、产出什么分类，以及如何影响后续 Skill 自动优化。
- 未加入默认兜底、mock 或静默忽略。

## 风险 / 说明

- 本 sprint 只建立分析契约，不声称账号稳定性或评论方向已自动计算。
- 评论区是强信号，但也容易被热门梗或站内情绪带偏；后续脚本需要同时记录样本标题、正文结构和评论证据，避免只按单条评论选题。
