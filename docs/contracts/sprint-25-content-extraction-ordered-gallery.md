# Sprint 25 合同：内容提取整组图文顺序理解

## 目标

修正 Sprint 23 的逐张图片理解方案：图文内容提取必须把同一作品的全部图片按 `display_order` 顺序一次性提交给 SiliconFlow 视觉模型，让模型结合前后页上下文后按页输出连贯内容。这个整组图文提取步骤替代旧的图文故事总结步骤。

## 范围内

- 图文内容提取从“逐张视觉调用 + 二次文本 LLM 整理”改为“一次多图视觉调用”。
- 多图请求中按图片顺序插入 `第 1 张图片`、`第 2 张图片` 等文本标记和对应 `image_url`。
- 提示词要求模型结合前后图片保持内容连贯，但输出仍按输入顺序逐页排列。
- 多图视觉模型返回直接写入 `content_extractions.extracted_text`，作为详情页主内容提取结果。
- 后台处理不再调用旧的图文故事总结步骤；`/summarize-story` 明确返回该步骤已被整组图片内容提取替代。
- 前端移除“故事总结”和“重新总结”入口，只展示内容提取主结果。
- `content_extraction_ai_debug` 日志记录一次多图请求的 prompt、图片输入摘要和模型返回内容。

## 范围外

- 不新增数据库字段。
- 不保留逐张视觉调用作为兜底。
- 不新增文本 LLM 二次整理步骤。
- 不改变视频音频转写链路。
- 不删除历史故事总结字段或迁移旧数据。
- 不自动把内容提取结果创建为 DoodleStory 生成任务。

## 完成标准

- 图文内容提取只对整组图片调用一次视觉模型。
- 新建图文内容提取任务不再生成 `故事内容`、`故事爆点`、`目标观众`。
- 详情弹窗只展示 `内容提取` 主结果，不展示故事总结区域。
- `backend/.venv/bin/python -m compileall backend/app`、`npm run build --prefix frontend`、`git diff --check` 和 `./scripts/check.sh` 通过。
