# Sprint 136：YouTube 列表分页与可读性

## Status

Complete。

## Goal

让管理员浏览频道账号和单频道已发布视频时使用清晰、稳定的服务端分页，并适度增大 YouTube
管理页面文字，减少长列表和小字号带来的阅读负担。

## In scope

- 频道账号列表固定每页 10 条，使用现有后端 cursor/limit 分页和 total，不再一次加载 100 条。
- 新增单频道已发布视频分页 API，按 `uploaded_at DESC, id DESC` 稳定排序，每页 10 条。
- 频道详情不再通过嵌套关系无界加载已发布视频；视频 Tab 独立请求当前页。
- 搜索或状态筛选变化时回到第一页；上一页、下一页显示明确禁用状态。
- 同步频道后刷新当前频道页；同步视频后刷新视频第一页和总数。
- 分页区域显示当前页、总页数和总条数。
- YouTube 频道管理范围内的正文、表格、辅助文字、状态和表单字号整体上调约 1–2px，保持现有
  深色 Agent Studio、暖橙单一强调色和紧凑扁平表格。

## Out of scope

- 发布任务、对标账号、可发布视频选择器或 Native Agent 对话列表分页。
- 修改远端 YouTube 同步接口、自动轮询或后台同步。
- 全站字体系统重做、布局重构或移动端导航改版。
- 新增数据库表或迁移。

## Done means

- 17 个频道分成两页显示，翻页时只请求对应 10 条，搜索和状态筛选不会停留在无效页码。
- 单频道视频列表只读取当前页，能够前后翻页，并显示准确总数。
- 频道详情请求不再加载完整已发布视频关系。
- 分页按钮有加载与边界禁用状态，空列表与加载错误仍可辨认。
- 频道管理页面的小字明显更易读，同时不破坏既有表格密度和响应式布局。

## Verification

1. 后端测试覆盖频道分页、视频分页、频道隔离、稳定顺序和管理员权限。
2. 前端生产构建通过。
3. 真实浏览器验证频道第二页、返回第一页、视频翻页和字号层级。
4. 运行 `./scripts/check.sh` 和 `git diff --check`。

## Verification result

- `./scripts/check.sh` 通过：312 项后端测试、空 SQLite 全量 Alembic 迁移、前端生产构建、
  Remotion TypeScript 检查和 5 项模板测试均通过。
- YouTube 定向测试 12 项通过；新增覆盖频道有界分页、视频按频道隔离、稳定倒序、第二页边界和
  普通用户权限。
- 真实浏览器验证 17 个频道按 10/7 分为两页，73 个视频按 10 条分为 8 页；上一页和下一页在
  边界正确禁用，第二页数据发生实际变化，浏览器控制台无错误。
- 视觉验收确认正文、表头、辅助信息、状态和表单文字上调约 1–2px 后仍保持原有紧凑表格密度，
  未出现列错位或强调色漂移。
- `git diff --check` 通过。

## Handoff

本 Sprint 不改变 Sprint 135 的发布任务与结构化 `@频道` 合同；后续如果发布任务数量增长，应在
独立 Sprint 中使用同样的服务端分页方式处理。
