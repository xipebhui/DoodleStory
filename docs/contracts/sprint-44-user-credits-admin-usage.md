# Sprint 44 合同：用户积分、激活码与管理员使用管理

## 目标

为 DoodleStory 增加第一版用户积分体系，让用户生成图片时按成功产出扣积分，并让管理员可以查看用户使用情况、调整积分和生成激活码。普通用户需要在工作台左下角实时看到当前积分余额，并能在设置页兑换激活码。

## 范围内

- 新增积分账户和积分流水：
  - 新注册用户默认获得 `30` 积分。
  - 当前已经注册的用户在迁移时统一初始化为 `1000` 积分。
  - 积分流水必须记录初始赠送、管理员调整、激活码兑换、图片生成占用、成功扣费和失败释放。
- 新增激活码能力：
  - 管理员可生成固定积分面额的单次兑换码。
  - 用户可在设置页输入激活码兑换积分。
  - 激活码兑换后不可重复使用；过期或禁用的激活码不能兑换。
- 新增管理员用户管理：
  - Admin 可查看用户列表、积分余额、任务数量、成功图片数和消耗积分。
  - Admin 可手动增减用户积分，并必须填写原因。
- 接入生图扣费 hook：
  - 所有模型同价，成功产出一张图片扣 `1` 积分。
  - 正式任务 panel 图、任务重试、单 panel 修改、人物参考图和风格测试图都扣积分。
  - 内容提取本身不扣积分；DY 爆款复刻自动创建出的生成任务按普通任务生图扣积分。
  - 生图请求前占用 `1` 积分，Provider 失败或未产出图片时释放，占用成功且图片资产保存成功后转为实际扣费。
  - 积分不足时必须明确失败，不调用图片 Provider。
- 前端设置页和工作台展示：
  - 普通用户在左下角稳定看到当前积分余额。
  - 设置页展示当前余额、可用余额、占用积分、最近积分流水和激活码兑换入口。
  - Admin 设置页额外展示用户管理、积分调整和激活码生成入口。
- 更新产品规格、进度记录和相关 API/数据库设计说明。

## 范围外

- 不接入在线支付、充值订单、套餐订阅或第三方支付平台。
- 不做多币种、分模型差异定价、团队共享额度或组织级额度池。
- 不引入外部队列、支付状态机或复杂计费引擎。
- 不为内容提取、LLM 文案处理、下载打包单独计费。
- 不做用户自助购买记录或发票管理。

## 完成标准

- Alembic 空库迁移可以升级到 head，已有用户迁移后获得 `1000` 积分账户。
- 新用户注册后获得 `30` 积分，并产生初始赠送流水。
- 正式任务、单 panel 修改、人物参考图和风格测试成功出图后都扣 `1` 积分。
- Provider 失败时释放占用，不产生最终扣费。
- 积分不足时不调用 Provider，并写入用户可读错误。
- Admin 可以分页查看用户积分与使用摘要，可以调整积分并生成流水。
- 用户可以兑换激活码，重复兑换、禁用码和过期码均明确失败。
- 普通用户左下角能看到积分余额；设置页能看到余额与最近流水。
- 后端单测覆盖积分服务、激活码、admin 权限和扣费 hook。
- `./scripts/check.sh` 通过，或明确记录未通过原因。

## 风险 / 说明

- 当前任务内 panel 生图支持并发，因此虽然产品口径是“成功出图扣费”，实现上仍需要在请求 Provider 前占用积分，避免用户余额在并发请求中被超用。
- 激活码明文只在生成接口响应中返回一次；数据库长期保存哈希，避免泄漏后可直接兑换。
- 管理员手动修改积分和用户自助兑换激活码最终都进入同一张积分流水，便于后续排查。
