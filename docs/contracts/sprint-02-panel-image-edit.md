# Sprint 02 合同：单 Panel 画面修改与图片版本

## 目标

支持用户对单个 panel 提交画面修改方向。系统调用一次 LLM 基于当前 `image_prompt` 生成新的画面提示词，再重新生成该 panel 图片，并让用户在任务详情中看到修改过程和历史版本。

## 范围内

- 将 `generated_images` 从“每个 panel 唯一图片”升级为“每个 panel 的图片版本表”。
- 为 `generated_images` 增加版本号、当前版本标记、来源类型、流程步骤、用户修改方向、修改前 prompt、修改后 image prompt、修改摘要和 LLM 模型快照。
- 保留旧图片和旧 prompt，不覆盖历史版本。
- 新增单 panel 修改接口，提交后返回任务详情并异步执行：
  - LLM 改写 panel image prompt。
  - 使用新 prompt 重新生成该 panel 图片。
  - 成功后将新图片标记为当前版本。
- 任务详情前端支持：
  - 输入单 panel 修改方向。
  - 展示当前修改流程状态。
  - 展示每个 panel 的图片版本列表。
  - 预览和批量下载只使用当前成功图片。

## 范围外

- 不引入外部队列或独立 worker 服务。
- 不支持一次生成多个候选图。
- 不支持手动编辑最终 prompt。
- 不做版本删除、回滚到旧版本或版本对比图 UI。
- 不做用户修改方向的数据分析后台。

## 交付物

- Alembic migration。
- 后端模型、schema、任务接口和单 panel 修改执行逻辑。
- LLM 单 panel prompt 修改提示词。
- 前端任务详情中的 panel 修改入口和版本过程展示。
- 更新项目规格和进度记录。

## 完成标准

- 现有任务生成仍能为每个 panel 创建初始图片版本。
- 单 panel 修改会新增 `generated_images` 版本，不覆盖旧版本。
- 修改过程中可看到 `rewrite_prompt` / `generate_image` 状态。
- 成功后只有新版本作为当前版本展示和下载。
- 失败版本保留错误信息，不影响旧的当前成功图。
- 普通用户只能修改自己任务下的 panel，Admin 可修改所有任务。
- 已运行 `./scripts/check.sh`。

## 验证

```bash
./scripts/check.sh
```

人工检查：

- 创建或打开已有任务，确认任务详情仍能显示当前图片。
- 对单个 panel 提交修改方向，确认出现新版本和流程状态。
- 修改成功后，确认当前图切换到新版本，旧版本仍留在历史中。
- 批量下载只包含当前成功图片。

## 风险 / 备注

- 当前采用应用层保证每个 panel 只有一个 `is_current=true` 的成功版本，没有引入数据库 partial unique index。
- 单 panel 修改使用进程内异步任务执行；如果进程在修改中重启，运行中的版本可能需要后续恢复策略补强。
