# Sprint 102 合同：图文逐图内容提取与 LIO 备用重试

## Goal

把抖音图文内容提取从“整组图片一次理解连续故事”改为“一张图片一次提取可见内容”，让每张原图严格对应一份可用于复刻的画面描述；当 `TEXT_FALLBACK_*` 当前指向的火苗主平台对某张图片提取失败时，切换到现有 `LIO_*` OpenAI 兼容平台，对同一张图片最多发起 3 次 LIO 请求，全部失败后才让整个内容提取任务失败。

## User-Authorized Behavior Change

- 用户已明确不再需要从整组图片中提取或理解连续故事，只需要逐张提取图片实际可见内容用于复刻。
- 用户已明确授权主平台失败后切换到 LIO，不再沿用 Sprint 98 的“图文 VL 不设备用平台”限制。
- 备用平台复用现有 `LIO_API_KEY`、`LIO_BASE_URL` 和 `LIO_MODEL`，不新增第三套密钥配置。

## In Scope

- 图文图片严格按 `display_order` 顺序逐张提交，每次请求只包含一个 `image_url`。
- 单图 prompt 只提取当前图片可见的分格、构图、人物、动作、表情、环境、道具、色彩、光线、原文文字和文字布局。
- 单图 prompt 禁止推断前后故事、补写上下文、总结剧情或改写图片内文字。
- 后端为每张单图结果确定性添加 `第X页` 页标，再按原始图片顺序合并为现有 `extracted_text`，保持后续 `提取分镜` 输入契约。
- 每张图片先调用 `TEXT_FALLBACK_*` 主平台一次；主平台配置、请求、空响应或结构校验失败时，切换到 LIO。
- LIO 对同一张图片最多发起 3 次请求；请求或响应错误可重试，重试间采用有界退避；LIO 配置缺失属于永久错误，立即明确失败。
- 任意图片在主平台失败且 LIO 3 次均失败时，整个内容提取任务失败，不跳过图片、不保存占位结果。
- 保持视频音频转写、风格提示词提取、角色参考图理解和图片生成 Provider 不变。

## Out of Scope

- 不做跨页故事理解、人物关系推断或叙事连贯性改写。
- 不并行提交多张图片；本 Sprint 使用顺序逐图调用，确保调用顺序和结果顺序一致。
- 不让风格提示词提取自动切换到 LIO。
- 不增加第三个视觉理解平台。
- 不自动重跑历史内容提取记录。
- 不在单张图片失败时静默跳过、返回 Mock、占位文案或部分成功结果。

## Done Means

- N 张图产生 N 次独立主平台请求，每次请求只有一个图片 URL。
- N 份结果按原顺序合并为连续 `第1页` 到 `第N页`，不会由模型合页或漏页。
- 主平台单图请求成功时不调用 LIO。
- 主平台单图请求失败时只针对该图调用 LIO，前两次失败、第三次成功时任务继续。
- LIO 3 次均失败时返回包含具体图片序号的明确错误，任务标记失败。
- 现有 LIO 单图真实冒烟测试通过，自动化测试覆盖逐图调用、结果顺序、备用切换、3 次上限和失败边界。

## Risks / Notes

- 逐图调用会把一次整组请求增加为 N 次请求，并相应增加总请求开销和串行耗时，这是用户为单页提取准确性明确接受的方向。
- 不同图片独立提取后，对跨页同一人物的称呼可能不一致；当前目标是复刻每张图片的可见内容，不再以跨页叙事一致性为优先级。
- `TEXT_FALLBACK_*` 是既有通用配置名，当前部署指向火苗；代码按配置驱动，不把域名硬编码进业务逻辑。
