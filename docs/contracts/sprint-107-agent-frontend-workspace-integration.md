# Sprint 107：传统构建与 AI 构建前端整合

## Status

Active（2026-07-22）。Sprint 106 已完成；用户已确认在新窗口开始本 Sprint。

## Goal

把已完成的 Agent 会话前端与 DoodleStory 现有正式工作台整合为同一个产品：继续使用现有全局侧边栏、账号和资源入口，在图文创作主区域顶部提供 `传统构建 / AI 构建` 两种模式；传统模式保留现有任务页，AI 模式承载真实会话、Agent 状态和任务卡片，并让 Agent 创建的同一个 `GenerationTask` 可以进入现有任务详情。

本 Sprint 只解决正式前端的信息架构、路由、真实数据和核心交互，不增加新的 Agent 创作能力。

## In scope

- 保留现有 DoodleStory 全局 Shell：品牌、主导航、积分、用户信息和风格/角色等资源管理入口继续只有一套。
- 移除正式工作台中独立的 `漫画 Agent` 一级导航语义；`图文任务` 是图文创作入口，`/tasks` 与 `/agent` 都应使该入口保持选中或处于同一创作模块语义。
- 在传统任务页与 Agent 页面顶部提供同一组清晰可见的 `传统构建 / AI 构建` 分段切换控件。
- 模式使用稳定 URL：`传统构建` 导航到 `/tasks`，`AI 构建` 导航到 `/agent`；浏览器刷新、前进、后退和直接打开链接后，模式必须与 URL 一致。
- 把 Sprint 103 独立 Demo 已确认的会话交互移入正式 `/agent` 页面，但不复制 Demo 的第二套 Logo、`Agent Studio` 全局外壳、假数据或尚未实现的操作。
- AI 模式保留自己的会话历史侧栏、当前对话、空白新对话、历史会话恢复、输入区、应用级运行状态和对话内任务卡片。
- 继续使用 Sprint 106 的真实 Conversation、Message、Run、Task Card 和风格接口；风格选择必须提交真实 style ID，不引入前端硬编码资源。
- Agent 任务卡片提供进入 `/tasks/{task_id}` 的明确入口；现有任务列表继续展示同一个 `generation_tasks` 记录，不复制任务或建立 Agent 专用任务列表表。
- 覆盖必要的加载、空状态、失败、进行中、完成、禁用和键盘焦点状态；轮询和会话切换不得丢失输入草稿或当前 URL 上下文。
- 只做实现当前布局所需的局部组件拆分；允许抽取共享模式切换、Agent 会话侧栏、任务卡片等组件，不在本 Sprint 全量重构 `frontend/src/main.tsx`。

## Out of scope

- 不实现固定角色、临时角色、`@角色` 的后端解析或生图引用；角色仍通过现有 `角色管理` 入口维护，但 AI 模式不展示一个看似可用、实际未生效的角色引用入口。
- 不实现用户维度 Memory、创作习惯、用户规则或自定义 Skill。
- 不实现 Panel 修改、重新生成版本、版本恢复、`inspect_image` 或 VL 闭环；这些属于 Sprint 108。
- 不实现抠图、Remotion、文字转语音、视频解说或其它多媒体 Tool。
- 不实现 `@任务/@Panel/@图片版本`、参考漫画、抖音输入、知识方案或旧 Pipeline 迁移。
- 不新增 Agent 数据库表、通用资源表、任务来源字段、Tool 注册平台、外部队列或多 Agent。
- 不改变 Sprint 106 固定 `Idea + 一个风格 + 两格漫画` 的后端能力边界。
- 不删除独立 Demo；它继续作为历史交互参考，但不是正式页面运行依赖。
- 不进行移动端重设计；本 Sprint 桌面端优先，只保证合同指定桌面视口可用且无横向内容丢失。

## Required interaction behavior

1. 已登录用户访问 `/tasks` 时看到原有传统任务体验，顶部 `传统构建` 为选中状态。
2. 点击 `AI 构建` 后 URL 进入 `/agent`，全局 Shell、用户、积分和主导航不重建为第二套产品外壳。
3. `/agent` 默认可以新建空白会话，也可以从有界历史列表恢复旧会话；切换会话时读取真实 API 数据。
4. 用户选择一个真实 active 风格并提交 Idea 后，继续使用 Sprint 106 链路创建真实两格任务。
5. 任务运行状态在对话卡片原位更新；刷新或重新进入会话后可以从数据库恢复。
6. 点击 Agent 任务卡片中的查看入口进入 `/tasks/{task_id}`；该 ID 与传统任务列表中的任务 ID 相同。
7. 从任务详情返回或再次切换到 AI 构建时，稳定 URL 和可恢复服务端状态仍能重新进入对应工作区；不得依赖只存在于内存的假任务。

## Done means

1. 正式产品只有一套全局侧边栏和品牌框架，传统与 AI 构建通过顶部控件切换。
2. `/tasks`、`/agent`、`/agent/{conversation_id}` 和 `/tasks/{task_id}` 的刷新、前进、后退和直接访问行为稳定。
3. Agent 页不包含独立 Demo 的假对话、假资源、假任务或尚未接通的角色/Panel 操作。
4. 用户可以完成“进入 AI 构建 → 新建/恢复会话 → 选择真实风格 → 提交 Idea → 查看真实任务卡片”的链路。
5. Agent 创建的任务可在传统任务列表中找到，并可从 Agent 卡片打开同一个任务详情，不产生第二份任务数据。
6. 传统任务创建、列表、筛选、任务详情及其它左侧导航页面没有回归。
7. 1440×900 和 1280×800 桌面视口布局可用；主要操作可用键盘访问，浏览器控制台无 error。
8. 前端生产构建、相关自动化检查、`git diff --check` 和 `./scripts/check.sh` 通过。

### Browser regression

至少在 1440×900 和 1280×800 真实浏览器完成：

1. 登录后进入 `/tasks`，确认传统模式选中且原任务列表可用。
2. 切到 `/agent`，确认全局 Shell 保持一致且没有第二套品牌导航。
3. 新建空白会话、切换历史会话并刷新恢复。
4. 选择真实风格、提交真实 Idea，看到运行状态与两格真实任务卡片。
5. 从 Agent 卡片打开 `/tasks/{task_id}`，确认传统任务列表可找到同一 task ID。
6. 使用浏览器后退、前进和强制刷新检查模式与对象上下文。
7. 检查加载、空状态、失败状态、窄桌面布局、键盘焦点和控制台错误。

真实模型或图片 Provider 如果因外部状态无法完成，不得改用 Mock 或占位结果；应保留已有 Sprint 106 证据，并明确记录本次未完成的外部验收项。
