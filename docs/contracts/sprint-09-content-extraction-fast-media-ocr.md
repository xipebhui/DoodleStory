# Sprint 09 合同：内容提取下载先展示与本地 OCR

## 目标

优化内容提取任务的可见进度和处理速度：抖音下载完成并登记媒体后，前端详情应能立即看到下载图片；图文文案提取改为本地 Python OCR SDK，不再逐图调用多模态 AI。故事总结继续使用 AI。

## 范围内

- 后端后台处理流程拆成可提交阶段：
  - 创建任务后保持 `processing`。
  - 下载完成并保存媒体资产后立即提交数据库，让详情接口可以返回媒体。
  - OCR 完成后再次提交，让详情接口可以先看到原始文案。
  - 故事总结完成后标记任务 `succeeded`。
- 图文 OCR：
  - 使用 `rapidocr-onnxruntime` Python SDK。
  - 保持图片顺序逐张识别并合并文本。
  - OCR 失败必须让任务明确失败，不能静默跳过。
- 故事总结：
  - 继续使用 SiliconFlow 视觉模型。
  - 不改变故事总结字段和前端展示结构。
- 前端提示文案更新为“下载完成先显示媒体，本地 OCR 提取文字，AI 总结故事”。
- 更新 `docs/spec.md` 和 `docs/progress.md`。

## 范围外

- 不引入外部队列、独立 worker、取消机制或复杂状态机。
- 不为 OCR 增加 AI 兜底或静默降级。
- 不改变视频音频转写路径。
- 不改变下载服务接口。
- 不把下载服务返回的服务器绝对路径暴露给浏览器。

## 完成标准

- `backend/requirements.txt` 包含本地 OCR SDK 依赖。
- 图文 OCR 不再调用 SiliconFlow 多模态接口。
- 下载完成后，即使任务仍在 `processing`，详情接口也能返回媒体数组。
- OCR 完成后，即使故事总结仍在处理，详情接口也能返回 `extracted_text`。
- `./scripts/check.sh` 通过。
- 使用真实图文链接验证下载后媒体可提前可见。

## 验证

自动验证：

```bash
./scripts/check.sh
```

人工验证：

1. 创建一条图文内容提取任务。
2. 在任务仍为 `processing` 时打开详情。
3. 确认下载媒体先于故事总结展示。
4. 等待任务完成，确认 OCR 文案和故事总结正常显示。
