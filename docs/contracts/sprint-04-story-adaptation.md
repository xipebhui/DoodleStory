# Sprint 04 合同：故事方案增强模式

## 目标

支持用户输入“故事方案”或“简化故事”。开启后，系统先调用 LLM 将用户输入整理成更适合抖音图文/短视频传播的故事，包括标题、钩子、完整改写故事和更强的冲突推进，再进入后续分镜、人物参考和图片生成流程。

## 范围内

- 任务创建接口和前端创建弹窗增加 `story_input_mode`：
  - `original`：完整故事模式，保持现有流程。
  - `adapted`：故事方案增强模式，先改写故事再生成。
- 数据库在任务表保存：
  - 原始输入 `original_text`，仍然不改写。
  - 增强后的标题 `adapted_story_title`。
  - 增强后的完整故事 `adapted_story_text`。
  - 增强钩子 `adapted_story_hook`。
- 任务步骤新增 `adapt_story`，仅 `adapted` 模式执行。
- 分镜表新增：
  - `panel_type`：`cover` 或 `scene`。
  - `narration_text`：旁白文字。
  - `dialogue_text`：人物对白，使用可读文本格式保存。
- `adapted` 模式分镜规则：
  - 第一张必须是封面 `cover`。
  - 封面包含故事标题、钩子和核心视觉画面。
  - 普通分镜区分旁白和人物对白。
  - 用户指定固定图片数量时，数量包含封面，例如 8 张表示 1 张封面 + 7 张剧情图。
- 生图最终 prompt 需要明确：
  - 封面图展示标题和钩子。
  - 旁白作为旁白/字幕区呈现。
  - 对白作为角色附近的对话气泡呈现。
  - 不添加输入结构之外的无关文字。

## 范围外

- 不做用户手动编辑增强故事。
- 不做人设人工编辑。
- 不重做任务详情整体 UI。
- 不引入外部队列或新的工作流基础设施。
- 不删除或替换普通故事模式。

## 完成标准

- 普通故事模式行为保持兼容。
- 故事增强模式会多一个 `adapt_story` 步骤。
- `adapted` 模式成功后，任务保存增强标题、钩子和完整故事。
- `adapted` 模式的第一个 panel 是封面。
- panel 生图 prompt 能区分封面、旁白和对白。
- 前端创建任务可以选择输入模式。
- 任务详情能看到增强故事和 panel 的旁白/对白信息。
- 已运行 `./scripts/check.sh`。

## 验证

```bash
./scripts/check.sh
```

人工检查：

- 创建普通任务，确认没有执行 `adapt_story`。
- 创建故事方案增强任务，确认步骤包含 `adapt_story`。
- 固定数量任务确认总 panel 数等于指定数量，且第一个 panel 是封面。
- 查看最终 prompt，确认封面标题/钩子、旁白、对白分别进入文本要求。

## 风险 / 备注

- 故事增强是显式模式，不会在普通故事模式下自动改写用户输入。
- 增强失败时任务失败并展示错误，不生成占位故事，不静默改回普通模式。
