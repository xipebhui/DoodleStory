# Sprint 04 合同：故事方案增强模式

## 目标

支持用户输入“故事方案”或“简化故事”。开启后，系统调用 LLM 直接规划图文 storyboard，识别用户方案中显式或隐式的 panel 逻辑，输出标题、钩子、规划概要、每张图的画面内容、图片内文字和文字布局，再进入人物参考和图片生成流程。

## 范围内

- 任务创建接口和前端创建弹窗增加 `story_input_mode`：
  - `original`：完整故事模式，保持现有流程。
  - `adapted`：故事方案增强模式，先改写故事再生成。
- 数据库在任务表保存：
  - 原始输入 `original_text`，仍然不改写。
  - 增强后的标题 `adapted_story_title`。
  - 图文分镜规划概要 `adapted_story_text`。
  - 增强钩子 `adapted_story_hook`。
- 任务步骤新增 `adapt_story`，仅 `adapted` 模式执行；该步骤现在承担故事方案 storyboard planning。
- 分镜表新增：
  - `panel_type`：`cover` 或 `scene`。
  - `narration_text`：旁白文字。
  - `dialogue_text`：人物对白，使用可读文本格式保存。
  - `image_text_json`：图片内文字结构。
  - `text_layout`：文字布局建议。
- 生成图片表新增：
  - `image_text_json`：每次图片版本使用的图片内文字快照。
  - `text_layout`：每次图片版本使用的文字布局快照。
- `adapted` 模式分镜规则：
  - 第一张必须是封面 `cover`。
  - 封面包含故事标题、钩子和核心视觉画面。
  - 普通分镜区分旁白和人物对白。
  - 用户指定固定图片数量时，数量包含封面，例如 8 张表示 1 张封面 + 7 张剧情图。
- 生图最终 prompt 使用 Markdown 模板渲染，需要明确：
  - 封面图展示标题和钩子。
  - 旁白作为旁白/字幕区呈现。
  - 对白作为角色附近的对话气泡呈现。
  - 不添加输入结构之外的无关文字。

## 范围外

- 不做用户手动编辑增强故事。
- 不做人设人工编辑。
- 不重做任务详情整体 UI，只补充图片内文字和文字布局的基础展示。
- 不引入外部队列或新的工作流基础设施。
- 不删除或替换普通故事模式。

## 完成标准

- 普通故事模式行为保持兼容。
- 故事方案模式会多一个 `adapt_story` 步骤。
- `adapted` 模式成功后，任务保存标题、钩子和图文分镜规划概要。
- `adapted` 模式的第一个 panel 是封面。
- panel 生图 prompt 能区分封面、旁白、对白、强调文字和文字布局。
- 前端创建任务可以选择输入模式。
- 任务详情能看到图文分镜规划概要、panel 的图片内文字和文字布局信息。
- 已运行 `./scripts/check.sh`。

## 验证

```bash
./scripts/check.sh
```

人工检查：

- 创建普通任务，确认没有执行 `adapt_story`。
- 创建故事方案任务，确认步骤包含 `adapt_story`，并且该步骤直接生成 panels 和图文设计。
- 固定数量任务确认总 panel 数等于指定数量，且第一个 panel 是封面。
- 查看最终 prompt，确认使用 Markdown 模板，封面标题/钩子、旁白、对白、强调文字和文字布局分别进入模板变量。

## 风险 / 备注

- 故事方案规划是显式模式，不会在普通故事模式下自动改写用户输入。
- 规划失败时任务失败并展示错误，不生成占位分镜，不静默改回普通模式。
