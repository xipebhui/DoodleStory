# DoodleStory Agent 漫画创作工作台前端设计 Brief

## 如何使用本文档

将本文档完整交给负责前端设计或实现的 AI，并附上下面这句话：

> 请基于本文档直接实现一个可运行、可点击的高保真前端原型。不要先复述需求，不要制作营销落地页，不要把它设计成工作流搭建器。使用本地演示数据完成文档规定的核心交互，不需要接真实后端。

本文档用于让多个设计方案在相同产品目标和演示任务下独立发挥。以下内容分为两类：

- `必须满足`：产品语义、核心页面区域、交互路径、演示内容和状态表达。
- `允许发挥`：具体排版、色彩细节、字体、微动效、组件形态和空间比例。

不要为了追求差异而改写产品目标。

## 0. 最新方向：先设计 Agent 会话产品

本次设计首先验证的是 Agent 产品如何被使用，而不是漫画图片如何铺满画布。

首要问题是：

1. 用户怎么开启一个新对话。
2. 用户怎么查看历史对话并重新进入。
3. 对话离开后，已经创建的漫画任务如何继续运行。
4. 用户回到旧对话后，如何看到任务最新状态。
5. 漫画任务如何作为消息卡片出现在对话中。
6. 用户如何从任务卡片打开任务详情、选择某个 Panel，再回到对话继续修改。

结构化分镜画布属于“任务详情”，不是产品首屏。不要一进入页面就用大画布替代对话历史和会话入口。

### 0.1 最新正式产品整合约束

Sprint 107/108 曾把 Agent 嵌入旧工作台 Shell，并使用顶部 `传统构建 / AI 构建` 切换；该实现保留为历史完成记录，但其产品层级已被 2026-07-23 的后续决策替代。Sprint 111 及之后以下约束优先于后文旧原型描述：

- `/agent` 是独立创作模块，左侧只承担新对话、搜索和历史会话，不常驻旧图文任务、内容提取、风格、角色等后台导航。
- Agent 页面不显示 `传统构建 / AI 构建` 分段切换；只保留一个低层级“返回传统工作台”入口。
- Agent 模块继续复用 DoodleStory 登录用户、积分、Style、Character、GenerationTask、Panel、GeneratedImage 和 FileAsset 数据，不建立第二套业务表。
- Agent 任务卡片的查看入口进入 AI 专属检查器 `/agent/{conversation_id}/tasks/{task_id}`，不把旧 `/tasks/{task_id}` 详情当作 Agent 共同创作界面。
- 正式页面只接真实 Conversation、Message、Run、Resource、Artifact、Approval、Event 和 Task 数据；独立 Demo 中的确定性假数据不得进入生产代码。
- 后端尚未完成的角色、Panel、图片版本、VL、版本、暂停或其它写操作不得显示为可用按钮；对应能力在各自 Sprint 中与真实后端一起开放。

当前实施边界以 `docs/contracts/sprint-111-agent-independent-shell-readonly-inspector.md` 和 Agent V1 全局路线图为准。

## 1. 产品背景

DoodleStory 是一个把 idea、故事文本或参考作品创作成连续漫画图片的产品。

新版本不再以“填写表单并提交固定 Pipeline”为核心，而是由一个持续理解上下文的漫画导演 Agent 完成创作。Agent 会根据用户目标自主规划故事、角色、分镜和生图提示词，调用生图与视觉理解工具，查看生成结果，并根据质量决定接受、修改或重新生成。

用户会通过自然语言持续参与，例如：

- “把这个 idea 做成五格漫画。”
- “主角使用我保存的角色林夏。”
- “第 3 张表情更紧张，衣服和场景不要变。”
- “这个版本不如上一版，恢复 v1。”
- “结尾换成雨停后的清晨。”

这个产品首先是创作工具，其次才是任务监控工具。

## 2. 设计任务

设计一个桌面端优先的 Agent 漫画创作工作台，让用户完成：

1. 新建一个空白对话。
2. 从历史列表重新进入一个进行中或已完成的对话。
3. 与 Agent 对话，并理解 Agent 当前正在做什么。
4. 在对话中看到 Agent 创建的漫画任务卡片和实时状态。
5. 从任务卡片打开任务详情，按顺序查看整组漫画分镜。
6. 选中某个 Panel 或图片版本，并带回对话继续修改。
7. 通过 `@` 引用风格、角色、任务和具体 Panel。
8. 接受、重试、恢复或继续修改一张图片。

设计应体现“人和 Agent 在同一张数字分镜桌上共同工作”，而不是“用户向黑盒提交任务”。

## 3. 核心设计意图

### 3.1 Visual thesis

一个安静、专注、具有编辑感的创作会话空间：用户先看懂正在与哪个 Agent 对话、这个对话里有哪些任务，再按需进入图片详情。状态和控制清晰，但不把页面做成任务监控后台。

推荐延续 DoodleStory 当前深色工作台的品牌基础：接近墨黑的背景、层次清晰的中性表面、偏白正文和一个暖色强调色。允许设计者提出更好的单一视觉方向，但不得使用多色渐变、霓虹科技装饰或通用 SaaS 仪表盘风格。

### 3.2 Content plan

首屏只承担五个任务：

1. 让用户能够新建对话或重新进入历史对话。
2. 告诉用户当前在哪个对话和漫画任务中。
3. 告诉用户 Agent 当前状态。
4. 让任务以清晰的消息卡片出现在对话里。
5. 让用户可以查看任务、选中对象并立即继续对话。

不设置营销 Hero、数据统计卡片、教程 Banner 或大段产品说明。

### 3.3 Interaction thesis

通过三种交互让工作台有“共同创作”的感觉：

1. 对话切换保持上下文：用户从历史列表进入旧对话时，消息、任务卡片和最新状态同时恢复。
2. 任务详情与对话上下文联动：点击 Panel 或版本后，对话输入区立即出现对应上下文标签。
3. Agent 状态在原位变化：任务卡和对应 Panel 显示规划、生成、检查和完成，不依赖全屏遮罩。

## 4. 与当前产品交互的区别

当前产品是：

```text
创建任务表单 → 任务列表 → 任务详情抽屉 → 分镜卡片 → 单卡修改
```

目标工作台是：

```text
新建或进入历史对话 → 与 Agent 对话 → 对话中出现任务卡片
                                      ↓
                             打开任务详情并选择对象
                                      ↓
                               回到对话继续修改
```

必须消除以下体验：

- 用户在开始创作前必须填写一大组模式和选项。
- 分镜只在很深的详情抽屉中出现。
- 每个 Panel 下方都堆叠 Prompt、调试信息、版本列表和修改文本框。
- 用户说“修改第三张”时，系统只能从纯文本猜测目标。
- Agent 的中间行动只表现为一个笼统的加载状态。

## 5. 画布边界

第一版的产品主体是“对话列表 + Agent 对话”。结构化分镜画布只在用户打开任务详情后出现，并且不是无限画布。

必须满足：

- Panel 有明确顺序。
- 用户能快速浏览整组漫画。
- Panel 可以被选中。
- 当前选中对象清晰可见。
- 画布允许横向浏览或自适应网格布局。
- 画布可以容纳生成中、检查中、已接受、需要处理等状态。

第一版不要实现：

- 无限缩放和平移。
- 任意节点连线。
- 用户搭建 Agent 工作流。
- 自由坐标和复杂自动布局。
- 把工具调用过程画成流程图。
- 类似视频剪辑器的多轨时间线。

用户创作的是漫画，不是在编辑 Agent 执行图。

## 6. 页面信息架构

### 6.0 历史对话侧栏

必须包含：

- 主操作`新对话`。
- 对话搜索。
- 按今天、昨天或更早时间分组的历史对话。
- 对话标题、最近状态摘要和更新时间。
- 进行中、已完成、等待用户回复等状态提示。

点击历史对话后，中心区域恢复该对话的消息和任务卡片。用户不需要先进入独立项目详情页，才能继续与 Agent 沟通。

### 6.1 当前对话栏

必须包含：

- 当前对话标题。
- 最近一次活动时间。
- 当前对话中的任务状态，例如 `正在生成 · 3/5 张`。
- `查看任务`入口；只有存在任务时才展示。
- 一个克制的对话级操作区，例如暂停或继续。

对话栏不承担全站完整导航，也不重复左侧历史列表。工作台需要尽可能保留横向空间。

### 6.2 Agent 对话区

主要职责：

- 展示用户消息和 Agent 回应。
- 展示 Agent 可理解的简短行动记录。
- 输入自然语言。
- 携带 `@风格`、`@角色`、`@Panel`、`@图片版本` 等上下文引用。

行动记录使用用户能理解的语言：

- `已整理故事方向`
- `正在生成 Panel 4`
- `Panel 4 人物外观检查通过`
- `Panel 3 的表情不符合剧情，准备生成新版本`

不要显示：

- 模型隐藏思维过程。
- 大段 JSON。
- 完整系统 Prompt。
- 无意义的“调用工具成功”。

对话输入区必须持续可见。选中任务详情中的对象后，输入区显示可移除的上下文标签，例如：

```text
[@Panel 3] [@当前图片 v2]
人物表情再紧张一点，其他都不要变……
```

### 6.3 对话内任务卡片

Agent 创建漫画任务后，任务必须作为一条可持续更新的消息卡片出现在对话中。

任务卡片至少展示：

- 任务标题。
- 当前状态和进度。
- 已完成图片数与总数。
- 各 Panel 的紧凑状态预览。
- `查看任务`和`在对话中引用`。

任务继续执行时，卡片在原位更新，不反复向对话追加大量重复进度消息。用户离开该对话后，任务仍可继续；重新进入对话时看到最新状态。

### 6.4 任务详情与结构化分镜

点击`查看任务`后打开侧栏、抽屉或次级工作区，按顺序展示 Panel：

- Panel 编号。
- 当前图片或稳定占位。
- 一句话剧情目标。
- 当前状态。
- 当前版本号。
- 被选中时的明确反馈。

图片之间应具有连续作品的感觉，而不是互不相关的素材库。关闭任务详情后，用户回到原对话位置继续聊天。

### 6.5 对象检查器

检查器只展示当前选中对象的详细信息，避免把细节堆在每张 Panel 卡片下面。

选中 Panel 时可展示：

- 剧情目标。
- 当前图片。
- Agent 的最新视觉检查结论。
- 当前版本和历史版本。
- `再生成一个版本`、`接受当前版本`、`恢复上一版` 等动作。`再生成一个版本`复用当前版本已经保存的最终生图 Prompt、风格和角色参考资源，只创建当前 Panel 的新版本，不覆盖旧版本，也不重新规划故事；正式功能需要在执行前明确展示积分成本。

选中角色时可展示：

- 角色名和参考图。
- 简短身份锚点。
- 出现在哪些 Panel。

选中风格时可展示：

- 风格名称和参考图。
- 简短风格描述。

Prompt、模型线路、Provider Request ID 等调试信息可以放在二级折叠区，不得占据检查器第一视觉层。

### 6.6 运行状态

页面必须让用户看懂 Agent 是：

- 空闲。
- 正在思考下一步。
- 正在调用文本模型。
- 正在生成图片。
- 正在用 VL 检查图片。
- 等待用户决定。
- 已暂停。
- 失败。

状态不能只使用颜色表达，需要搭配文字、图标或动效。

## 7. 推荐桌面布局

下面只是功能分区，不是要求逐像素照抄：

```text
┌─────────────────────────────────────────────────────────────────────┐
│ DoodleStory Agent Studio · 设计演示                                 │
├────────────────┬─────────────────────────────────┬──────────────────┤
│ ＋ 新对话      │ 被裁员的第七天 · 正在生成 3/5    │ 对话中的任务     │
│ 搜索对话       │                                 │                  │
│                │ 用户消息                        │ Panel 1  已完成  │
│ 今天           │ Agent 回应                      │ Panel 2  已完成  │
│ ● 当前对话     │                                 │ Panel 3  已完成  │
│ ○ 已完成对话   │ [漫画任务卡片 · 生成中 3/5]     │ Panel 4  生成中  │
│                │                                 │ Panel 5  等待中  │
│ 昨天           │ Agent 行动摘要                  │                  │
│ ◐ 等待回复     │                                 │ Agent 行动记录   │
│                │ [@风格] [@角色] 输入框          │ 在对话中修改     │
└─────────────────────────────────────────────────────────────────────┘
```

右侧任务详情只在用户点击`查看任务`后出现，可以关闭；关闭后中心对话恢复完整宽度。建议在 1440×900 桌面视口中完整表现主要工作区，不依赖浏览器整体纵向滚动。历史对话、消息和任务详情可以独立滚动。

允许设计者调整各区域位置和宽度，但必须保持：新建与继续对话入口清楚、对话始终是主工作区、任务属于某个对话、选中对象能带回对话。

## 8. 固定演示项目

所有对比原型使用同一项目，避免演示内容差异影响判断。

页面首次打开时默认进入一个空白对话，不自动打开下面的固定演示项目。空白页可以克制地展示少量用户常用角色和风格，但资源不能成为卡片墙或取代对话输入；用户从左侧历史列表进入固定演示项目后，才恢复该项目的消息、任务卡片和以下 Panel 状态。

### 项目信息

- 项目名：`被裁员的第七天，我开始在街角画画`
- 创作形式：5 张连续漫画
- 风格：`暖灰铅笔电影感`
- 主角：`林夏，29 岁，黑色短发，深绿色外套`
- 辅助角色：`阿布，橘白流浪猫`

### 故事概要

林夏被裁员后连续一周不敢告诉家人。她每天假装上班，却坐在街角给路人画速写。第七天，一只流浪猫一直守在她身边。有人把她画画的视频发到网上，傍晚时她收到第一笔真正属于自己的订单。

### 五个 Panel

1. `早高峰，林夏背着电脑包逆着人群走出地铁，神情疲惫。`
2. `她坐在街角展开速写本，身旁放着没有打开的电脑。`
3. `林夏收到家人询问工作是否顺利的消息，强忍情绪，橘白猫靠近她。`
4. `陌生女孩蹲在旁边看她画画，悄悄举起手机记录。`
5. `雨停后的傍晚，林夏收到第一笔头像订单，橘白猫趴在她脚边。`

### 初始状态

- Panel 1：`已接受 · v1`
- Panel 2：`已接受 · v1`
- Panel 3：`已生成 · v2 · 当前选中`
- Panel 4：`VL 检查中 · v1`
- Panel 5：`等待生成`

### Panel 3 检查结果

```text
人物与参考角色一致，服装和场景连续性正常；但表情过于平静，没有表现出收到家人消息时的紧张和愧疚。
```

### Panel 3 版本

- v1：表情明显悲伤，画面过于煽情。
- v2：构图和角色一致性更好，但表情过于平静。
- v3：由演示交互生成的新版本。

## 9. 必须完成的演示交互

原型不需要接真实后端，但以下交互必须真实可点击、状态可见，不能只做静态截图。

### 交互 A：开启一个新对话

1. 点击左侧`新对话`。
2. 中心区域进入明确的空白会话状态，而不是新建任务表单。
3. 用户可以直接输入，也可以选择一个示例开场。
4. 发送后出现用户消息和 Agent 回应。
5. Agent 创建任务时，任务卡片出现在当前对话中。

### 交互 B：离开并继续一个对话

1. 从当前对话切换到另一条历史对话。
2. 历史对话恢复自己的消息、任务卡片和最后状态。
3. 再切回原对话，用户刚才发送的内容仍然存在。
4. 任务卡片显示离开期间的最新状态，让用户理解任务不依赖页面停留。

演示可以用确定性的本地状态和定时器表达变化，但必须显式标注为设计演示，不能伪装成真实后端结果。

### 交互 C：查看任务并带回 Panel

1. 点击对话内任务卡片的`查看任务`。
2. 右侧任务详情出现，并展示 5 个 Panel 的状态。
3. 点击 Panel 4 后，只切换检查器的当前选择，不立刻修改输入区上下文；选择态和运行态必须使用不同视觉语义。
4. 点击`引用 Panel 4 并修改`，任务详情关闭或弱化。
5. 输入区出现 `@Panel 4`，用户无需再用纯文本说明目标。
6. 如果输入区已有草稿，引用操作只增加结构化上下文标签，不覆盖原有文字。

### 交互 D：通过对话修改选中 Panel

1. 发送示例指令：`重新处理第 4 张，只加强人物表情，构图不变。`
2. Agent 简短复述修改边界。
3. 原任务卡片在对话中更新，不创建一条无关联的新任务。

### 交互 E：引用资源

1. 点击输入框附近的资源入口。
2. 可以选择风格、角色或已有任务。
3. 选中后输入区出现可移除的 `@` 上下文标签。

### 交互 F：暂停和继续

1. `暂停任务`属于任务级操作，放在任务详情顶部，不放进某个 Panel 的版本操作区。
2. 暂停后不再启动新的 Panel、Agent 步骤、检查或重试；已经提交给图片 Provider 的请求允许完成并保存，不把“暂停”描述成“立即取消当前生成”。
3. 如果后续需要立即中止 Provider 请求，应设计为独立的`取消当前生成`能力，并单独说明 Provider 支持与积分退还语义。
4. 对话历史、任务卡片和任务详情都显示`已暂停`。
5. 点击`继续任务`后从下一个未完成 checkpoint 恢复，不重复生成已经完成的图片。

## 10. 视觉与组件约束

### 必须满足

- 新建对话、历史对话、消息和任务之间的归属关系必须一眼可懂。
- 漫画图片只在任务卡片和任务详情中承担视觉证据，不得压过主要会话路径。
- 使用清晰排版和空间层级，不依赖厚重阴影。
- 不把每块内容都放进卡片。
- 重复 Panel 可以使用卡片，因为图片和选择操作就是卡片本身的语义。
- 全局只使用一个主要强调色。
- 状态、错误、选择和禁用态都必须可辨认。
- 中文文字不能拥挤、截断或与按钮重叠。
- 支持键盘聚焦态，按钮有明确名称。
- 历史对话、当前对话和任务详情使用分隔和表面层级，而不是三层厚重外框。

### 避免

- 通用 Dashboard 卡片矩阵。
- 紫蓝渐变和发光边框堆叠。
- 大面积装饰性玻璃拟态。
- 每个状态都使用不同鲜艳颜色。
- 大量圆角胶囊和徽标。
- 在首屏直接展示完整 Prompt。
- 让 Agent 消息气泡占据大部分页面。
- 让检查器比生成图片更抢眼。
- 使用没有叙事关系的随机图库图片。

## 11. 动效建议

至少实现两种有意义的动效：

1. 任务详情选择变化：Panel 选择、对象信息和对话上下文同步过渡。
2. 对话切换：消息和任务卡片更新，但侧栏选择与页面骨架保持稳定。
3. Agent 生成状态：同一任务卡片内从准备、生成、检查到完成，不跳动整体布局。

动效应短促、稳定并尊重 `prefers-reduced-motion`。不要加入持续漂浮、装饰粒子或与操作无关的循环动画。

## 12. 响应式要求

本次评审以桌面端为主。

最低要求：

- 1440×900：历史对话、当前对话和按需打开的任务详情同时可用。
- 1280×800：不遮挡核心操作，允许压缩或覆盖式展示任务详情。
- 小于 900px：允许把历史列表和任务详情变成抽屉，以当前对话为主视图。

不要求为手机完成所有高级拖拽操作，但必须保证可以查看作品、发送消息和选择 Panel。

## 13. 技术与交付约束

- 交付可直接运行的前端原型，不只交付设计说明或静态图片。
- 使用本地演示数据，不接真实 API。
- 演示状态必须是确定性的，刷新后可回到初始状态。
- 不引入无限画布或重型流程图库。
- 如果在 DoodleStory 仓库中实现，优先沿用 React、TypeScript 和现有构建方式。
- 不要求复用当前 `main.tsx` 的任务详情结构；原型可以使用独立路由和组件。
- 不修改现有任务页面，不把原型伪装成已经接通后端的正式功能。
- 不生成 Mock 业务结果用于正式产品；本次本地原型中的演示数据必须明确标注为`设计演示`。

## 14. 评审标准

评审时优先观察以下问题：

1. 进入页面三秒内，是否知道如何开启一个新对话？
2. 是否知道如何回到一个旧对话继续工作？
3. 是否能理解漫画任务属于哪一个对话，以及离开后仍会继续？
4. 是否能从对话查看任务，再自然地返回原对话？
5. 是否能在两次操作内完成“选中第三张并提出修改”？
6. Agent 的行动是否可理解，但没有暴露噪声和隐藏思维？
7. 对话切换和任务状态变化是否稳定，不会让布局不断跳动？
8. 页面是否克制、有创作感，而不是通用管理后台？
9. 如果移除阴影和装饰，信息层级是否仍然成立？
10. 这个界面是否让用户愿意通过连续对话完成创作？

## 15. 非目标

本次前端原型不需要设计：

- Agent 后端实现。
- 真实模型调用。
- 计费和积分结算。
- 完整项目列表。
- 管理员页面。
- 风格库和角色库的完整 CRUD。
- 视频剪辑时间线。
- 多人协作。
- 无限画布。
- 生产环境异常恢复。

这些能力不应干扰本次对“新建/继续 Agent 对话 + 对话内任务 + 按需任务详情”核心体验的判断。
