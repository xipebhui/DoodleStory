# UI 设计

## 导航

DoodleStory 是一个创作型生产工具，第一屏应直接进入任务工作台，不做营销落地页。

主导航：

- 任务
- 风格
- 设置

全局辅助控制：

- 显示模式：`跟随系统`、`浅色`、`深色`
- provider 健康状态区域，等真实 provider 接入后再启用

## 信息架构

### 注册和登录

第一版需要用户注册和登录，但不做组织、团队或租户隔离。

页面：

- 注册
- 登录
- 退出登录
- 找回密码
- 账号设置

规则：

- 默认使用邮箱和密码注册登录。
- 注册成功后进入任务列表。
- 未登录用户访问任务、风格或设置页面时，跳转到登录页。
- 普通用户只能看到自己创建的任务。
- Admin 用户可以看到所有用户的任务，并在任务详情中看到任务归属用户。
- 暂不设计用户之间共享任务、团队空间或组织权限。

### 任务

任务是用户的主流程。

页面：

- 任务列表
- 创建任务
- 任务详情
- 图片预览弹窗
- 批量下载确认/进度弹窗

### 风格

风格是可复用的生成预设。

页面：

- 风格列表
- 创建风格
- 风格详情
- 编辑风格
- 风格测试面板
- 删除风格确认

## 任务列表

用途：查找历史生成任务、查看任务状态、创建新任务。

布局：

- 页面标题：`任务`
- 主操作：`创建任务`
- 搜索：任务标题或故事片段
- 筛选：状态、风格、创建时间
- 排序：默认按最新创建时间倒序
- 表格列：
  - 任务标题或故事片段
  - 创建用户，只有 Admin 可见
  - 风格
  - 状态
  - 进度
  - 图片数量
  - 创建时间
  - 更新时间

状态：

- 加载：使用高度稳定的表格骨架屏。
- 空状态：说明还没有任务，并提供 `创建任务`。
- 无结果：说明当前筛选没有匹配项，并提供 `清空筛选`。
- 错误：提供重试，保留当前筛选条件。

交互规则：

- 使用服务端有界分页。
- 普通用户列表只返回自己的任务。
- Admin 用户可以通过用户筛选查看全部任务。
- 点击任务标题进入任务详情。
- 从详情返回列表时保留筛选、分页和滚动位置。
- 行操作必须对键盘和触屏用户可访问，不能只依赖 hover。

## 创建任务

容器：完整页面或宽抽屉。若文本输入和风格选择需要更大空间，优先使用完整页面。

字段：

- 输入模式：分段控件，选项为 `完整故事` 和 `故事方案`。
- 原始文本：必填，多行文本框。
- 图片数量模式：分段控件，选项为 `自动` 和 `固定数量`。
- 固定图片数量：只在选择 `固定数量` 时显示的数字输入框。
- 风格：可搜索选择器，展示风格缩略图、名称和简短描述。provider、model 和模型参数不向普通用户展示。
- 使用参考人物：可选开关。开启后，任务会先识别主要人物并生成人物参考图，再用于后续分镜生图。该开关应明确提示会增加生成时间。

规则：

- 表单内不得改写原始文本。
- `故事方案` 模式需要提示用户：原始输入会保留，系统会直接规划连续图文分镜。
- 提交前做前端校验，提交时仍需后端校验。
- 原始文本和风格有效后，才允许点击 `创建任务`。
- 固定数量必须是产品配置允许范围内的正整数。
- `故事方案` 模式下固定数量就是最终图片张数，不额外插入特殊图片。
- 如果开启参考人物但故事中没有可识别的主要人物，任务失败并在详情中展示明确错误，不自动按普通任务继续。
- 提交失败时保留全部输入，并把焦点移动到第一个可处理错误。
- 提交成功后进入新任务详情页。

主操作：`创建任务`

次操作：`取消`

## 任务详情

用途：查看生成过程、检查中间结果、浏览图片并下载结果。

头部：

- 任务标题或故事片段标题。
- 状态徽标。
- 风格名称。
- 创建用户，只有 Admin 可见。
- 创建时间和更新时间。
- 根据状态显示主操作：
  - 已创建但未排队：`开始生成`
  - 排队、运行或重试中：`取消生成`
  - 已有生成图片：`下载图片`

主体区域：

- 原始文本：只读展示，必须是用户提交的原文。
- 增强故事：只在 `故事方案` 模式展示，包含 LLM 生成的标题、钩子和完整故事。
- 生成进度：当前步骤、进度计数、开始时间、最新用户可读错误。
- 人物参考：只在开启参考人物的任务中展示，内容仅包括人物参考图、姓名和年龄/外形阶段。生成中显示稳定占位；不展示内部人物分析、完整人物设定或 prompt。
- Panels：按顺序展示 panel 编号、片段文本、旁白、对白、生成 prompt、状态和图片结果。
- 图片：生成图片网格，展示 panel 编号、状态和预览操作。
- 活动记录：来自工作流步骤状态的事件轨迹。

状态：

- `queued`：展示等待状态，允许取消。
- `adapt_story`：展示正在整理故事方案。
- `segmenting`：展示 LLM 正在切分故事。
- `prompting`：展示正在生成生图 prompt。
- `generating images`：展示按 panel 生成图片的进度。
- `succeeded`：展示全部图片和下载操作。
- `partial_succeeded`：展示成功图片和失败 panel，允许任务级重试。
- `failed`：展示用户可读错误和是否可重试。
- `cancel_requested`：展示取消请求已提交。
- `cancelled`：保留已完成输出，不自动重试。

交互规则：

- 任务活跃时自动刷新，并显示刷新状态。
- 普通用户访问他人任务详情时返回无权限状态。
- Admin 可以查看所有任务详情。
- 失败 panel 不隐藏。
- 不用 panel 文本或生成 prompt 覆盖原始故事。
- 生成 prompt 可查看；单 panel 画面修改通过“用户修改方向 -> LLM 改写 image prompt -> 重新生图”的流程完成，不直接手动编辑最终 prompt。
- 开启参考人物的任务进行单 panel 修改时，仍应沿用该 panel 已绑定的人物参考图，不要求用户重新选择人物。
- 每个 panel 可保留多个图片版本，当前展示和下载使用当前成功版本。

## 图片预览弹窗

由点击图片触发。

要求：

- 弹窗打开后锁定焦点，关闭后焦点回到触发图片。
- 展示大图预览、panel 编号和 prompt 摘要。
- 操作：`下载图片`、`打开原图`、`关闭`。
- 键盘：`Escape` 关闭；存在多张图片时，方向键切换上一张/下一张。
- 预览外框不得改变、反色或扭曲生成图片。

## 批量下载

优先行为：

- `下载图片` 一次性生成包含所有可用图片的压缩包。
- 压缩包命名：`doodlestory-task-{task_id}.zip`。
- 压缩包内文件命名：`panel-{panel_order}-{image_id}.{ext}`。

交互：

- 如果压缩包可以即时生成，直接开始下载。
- 如果需要异步打包，创建下载任务并展示进度。
- 没有图片时禁用 `下载图片`，并说明原因。
- 如果部分 panel 失败，按钮仍叫 `下载图片`，确认文案说明会包含多少张图片。

## 风格列表

用途：管理可复用视觉风格。

布局：

- 页面标题：`风格`
- 主操作：`创建风格`
- 搜索：名称和描述
- 筛选：状态
- 排序：默认按更新时间倒序
- 卡片或表格字段：
  - 参考图缩略图
  - 名称
  - 状态
  - 最近测试时间
  - 更新时间

风格有视觉参考图，因此这里可以使用卡片。若列表需要强比较，也可以切换为表格。

状态：

- 必须包含加载、空状态、无结果和错误状态。
- 当风格数量可能增长时，必须使用服务端分页。

## 创建和编辑风格

字段：

- 名称：必填。
- 描述：选填。
- 状态：草稿或启用。
- 风格提示词：必填，多行文本框。
- 参考图片：选填，支持多图上传。

规则：

- 风格提示词按作者输入保存。
- provider、API key 和模型默认参数属于后台私密配置，不在普通用户 UI 中展示或编辑。
- 风格表单维护生图模型名，例如 `gpt-image-2`。
- 删除已保存的参考图需要确认。
- 如果已有任务引用某个风格，删除该风格应被阻止；除非后续产品明确设计归档策略。

主操作：

- `创建风格`
- `保存风格`

次操作：

- `取消`
- `测试风格`

## 风格详情和测试面板

风格详情展示：

- 名称、状态、描述。
- 参考图片画廊。
- 风格提示词。
- 最近风格测试记录。
- 使用该风格的任务。

风格测试面板：

- 测试文本：必填文本框。
- 只读组合 prompt 预览：
  - 测试文本
  - 风格提示词
- 主操作：`生成测试图`
- 结果区域：最近测试图、状态、错误和时间。

规则：

- 风格测试使用该风格绑定的生图模型名。
- provider、API key 和参数不暴露给普通用户。
- 不能静默切换生图模型名。
- 失败时用用户可读语言展示 provider 或校验错误，内部细节另存。

## 可访问性和主题

- 所有表单都有 label、辅助说明和可见焦点态。
- 弹窗遵循可访问焦点管理。
- 纯图标操作必须有 accessible name 和 tooltip。
- 状态不能只靠颜色表达，必须有文本或图标辅助。
- 前端实现时支持 `跟随系统`、`浅色`、`深色`。
- 生成图片不得被主题模式反色或重新着色。
