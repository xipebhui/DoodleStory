# 内容提取列表化 UI 设计

## 背景

当前 `内容提取` tab 同时承载创建、下载结果、文案结果和最近记录。随着新增 `故事总结` 步骤，页面需要从单次操作工作台调整为可管理的内容提取任务列表：

- 列表页负责查找和查看历史任务。
- 创建任务放入弹窗，只收集抖音分享文本并执行 `解析并下载`。
- 详情放入弹窗，展示下载媒体、提取文案和故事总结。
- 列表页不得加载所有图片；完整媒体只在打开详情后按需加载。

## 新增能力

在 `提取文案` 之外增加 `故事总结` 步骤。

故事总结输入：

- 图文内容：使用该内容提取记录下的所有图片，按 `display_order` 顺序输入视觉理解模型。
- 视频内容：本次 UI 设计不为视频自动设计图片总结入口；如果后续要支持视频故事总结，应单独设计视频帧或视频理解路径。

故事总结输出三个字段：

- `故事内容`：概括这组图片讲了什么，保留故事主线和情绪推进。
- `故事爆点`：指出最有传播力、反差、共鸣或转折的部分。
- `目标观众`：判断更适合哪些人看，以及他们可能被什么点吸引。

故事总结是分析结果，不替代 `提取文案` 的原始文案。`提取文案` 仍然要求不总结、不润色、不改写。

## 视觉方向

Visual thesis：深色内容运营工作台，信息密度更接近任务管理和素材库，少量缩略图只在详情中承担来源校验。

Content plan：

1. 列表页：筛选、搜索、查看内容提取任务。
2. 创建弹窗：粘贴分享文本，解析并下载。
3. 详情弹窗：按任务查看原始文案、故事总结和媒体。
4. 图片预览弹窗：在详情内部点击图片后放大查看。

Interaction thesis：

- 创建成功后关闭创建弹窗、刷新列表，并自动打开新记录的详情弹窗。
- 列表行点击打开详情弹窗；关闭详情后保留列表筛选、分页和滚动位置。
- 详情内的 `提取文案` 与 `总结故事` 是两个显式同步动作，各自显示忙碌态，不自动串联。

## 页面结构

### 主页面：内容提取列表

页面标题：`内容提取`

顶部区域：

- 左侧：标题、简短说明、抖音下载服务健康状态。
- 右侧：主按钮 `新建提取`。

筛选区：

- 搜索框：搜索链接、作品 ID、文案预览、故事总结预览。
- 媒体类型：`全部`、`图文`、`视频`。
- 处理状态：`全部`、`仅已下载`、`已提取文案`、`已总结故事`。
- 排序：默认 `最近更新`，可选 `最近创建`。

列表区使用紧凑表格，不使用大卡片：

| 列 | 内容 |
| --- | --- |
| 来源 | 抖音 URL 或短作品 ID，第二行显示原始输入预览 |
| 类型 | `gallery` / `video`，媒体数量 |
| 处理结果 | `已下载`、`文案已提取`、`故事已总结` 状态徽标 |
| 文案预览 | `extracted_text_preview`，最多两行 |
| 故事爆点预览 | `story_highlight_preview`，最多两行 |
| 更新时间 | `updated_at` |
| 操作 | `查看` |

列表空状态：

- 无数据：显示 `还没有内容提取记录`，主操作 `新建提取`。
- 无搜索结果：显示 `没有匹配的记录`，提供 `清空筛选`。

列表加载规则：

- 列表接口必须带 `limit` 和 `cursor`。
- 列表只返回摘要字段，不返回 `media` 数组。
- 列表不加载所有图片，不触发每行详情请求。
- 如果未来需要视觉识别，可只返回一个可选 `cover_thumbnail_url`，但第一版列表不需要图片列。

### 创建弹窗

触发：点击列表页 `新建提取`。

弹窗标题：`新建内容提取`

弹窗内容：

- 多行输入框：`抖音分享文本或链接`。
- 帮助文本：可以粘贴完整分享文案，后端只解析其中的抖音 URL。
- 健康状态：显示抖音下载服务是否可用。

底部操作：

- 主按钮：`解析并下载`。
- 次按钮：`取消`。

交互规则：

- 点击 `解析并下载` 后按钮进入忙碌态，禁止重复提交。
- 下载失败时弹窗不关闭，保留用户输入并显示明确错误。
- 下载成功后关闭创建弹窗，刷新列表，并打开详情弹窗。
- 不在创建弹窗里展示完整媒体，避免创建流程变成长详情页。

### 详情弹窗

触发：点击列表行或创建成功后自动打开。

弹窗标题区：

- 主标题：`内容提取详情`。
- 副标题：显示 `source_url`、作品 ID、媒体类型、更新时间。
- 状态徽标：`已下载`、`文案已提取`、`故事已总结`。

弹窗布局：

- 桌面：左右两栏。
  - 左栏是主要结果：`提取文案` 和 `故事总结`。
  - 右栏是来源信息：下载摘要、媒体预览、原始输入。
- 移动端：单列全屏弹窗，结果在前，媒体在后。

#### 结果区

结果区使用 tabs：

- `文案`
- `故事总结`
- `媒体`

`文案` tab：

- 大文本只读区域展示 `extracted_text`。
- 操作：`提取文案` / `重新提取文案`、`复制文案`。
- 说明：该区域展示原始文案，不做总结或改写。

`故事总结` tab：

- 三个并列或纵向区域：
  - `故事内容`
  - `故事爆点`
  - `目标观众`
- 操作：`总结故事` / `重新总结故事`、`复制总结`。
- 空状态：`还没有故事总结`。
- 图文记录且存在图片时启用 `总结故事`。
- 视频记录默认禁用 `总结故事`，显示 `当前故事总结仅支持图文图片`。

`媒体` tab：

- 下载摘要：媒体类型、媒体数量、作品 ID。
- 图文：默认只展示前 6 张缩略图，提供 `展开全部图片`。
- 视频：展示小尺寸播放器。
- 图片缩略图可点击放大，支持左右切换。
- 媒体项下方展示该图的单项 OCR 文本，默认折叠。

#### 侧栏信息

侧栏展示：

- 原始输入，折叠展示，支持复制。
- 解析后的 URL，支持复制。
- 模型处理信息：文案模型、故事总结模型、更新时间。
- 错误信息：下载、文案提取或故事总结失败时显示明确错误。

## API 摘要设计

### 列表摘要

`GET /api/v1/content-extractions?query=&media_type=&result_status=&limit=20&cursor=...`

列表响应只返回：

- `id`
- `source_url`
- `raw_input_preview`
- `media_type`
- `aweme_id`
- `media_count`
- `extracted_text_preview`
- `story_content_preview`
- `story_highlight_preview`
- `target_audience_preview`
- `has_extracted_text`
- `has_story_summary`
- `created_at`
- `updated_at`

列表响应不得返回：

- `media`
- 完整 `raw_input`
- 完整 `extracted_text`
- 完整故事总结字段
- 图片原图 URL 或所有缩略图 URL

### 详情

`GET /api/v1/content-extractions/{id}`

详情返回：

- 完整原始输入。
- 完整文案。
- 完整故事总结字段。
- 媒体数组和资产 URL。
- 每个媒体项的单项 OCR 文本。

### 故事总结

`POST /api/v1/content-extractions/{id}/summarize-story`

响应保存并返回：

```json
{
  "story_content": "这一组图片讲述了...",
  "story_highlight": "爆点在于...",
  "target_audience": "更适合..."
}
```

规则：

- 只有图文图片可调用。
- 输入所有图片时按 `display_order` 排序。
- 如果没有图片，返回明确错误。
- 模型失败时返回明确错误，不生成占位总结。
- 已有总结时再次点击 `重新总结故事` 会覆盖旧结果，这是用户显式动作。

## 数据字段建议

在 `content_extractions` 增加：

- `story_content`
- `story_highlight`
- `target_audience`
- `story_summary_model`
- `story_summarized_at`

如果后续需要记录故事总结原始模型输出，可增加 `story_summary_raw_response`；第一版 UI 不展示。

## 状态设计

列表行状态：

- `已下载`：有媒体，没有文案和故事总结。
- `文案已提取`：有 `extracted_text`。
- `故事已总结`：有三个故事总结字段。

详情动作状态：

- `提取文案中`：只锁定文案按钮，不锁死整个弹窗。
- `总结故事中`：只锁定故事总结按钮，不锁死文案查看。
- `下载失败`、`文案提取失败`、`故事总结失败`：在对应区域显示错误。

## 可访问性与焦点

- 创建弹窗和详情弹窗都使用 `role="dialog"` 与 `aria-modal="true"`。
- 打开弹窗后焦点进入标题或第一个主要控件。
- 关闭弹窗后焦点回到触发按钮或列表行。
- `Esc` 关闭弹窗；存在提交中动作时，关闭前提示会中断当前等待视图，但不取消后端同步请求。
- 图片预览弹窗继续支持 `Esc` 关闭和左右方向键切换。

## 验证重点

- 首屏进入 `内容提取` tab 时只请求列表摘要，不请求详情和媒体数组。
- 点击 `新建提取` 后创建弹窗打开，失败保留输入。
- 创建成功后列表刷新并打开详情弹窗。
- 点击列表行才请求详情。
- 详情里可分别执行 `提取文案` 和 `总结故事`。
- 图文故事总结返回三个区域：故事内容、故事爆点、目标观众。
- 多图详情默认不展开所有图片，展开是用户显式动作。
