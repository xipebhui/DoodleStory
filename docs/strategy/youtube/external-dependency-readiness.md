# YouTube 新赛道：外部依赖准备清单

用途：在开始任何新的 YouTube Agent 开发或真实实验前，用这份清单确认权限、数据、版权、媒体和
运营条件。所有密钥、Cookie、登录信息和个人数据必须留在受控配置中，不能写入本文件或 Git。

## 1. 频道与发布权限

- [ ] 已确定目标语言、目标地区、频道定位和受众，而不是只写“做 YouTube”。
- [ ] 已登记一个真实 YouTube 频道，账号所有权、操作者角色和发布责任人明确。
- [ ] 已确认频道所在国家 / 地区、两步验证和 AdSense 责任主体；若未来申请 YPP，已核对该地区是否在
  官方开放范围内。达到订阅 / 观看门槛不等于自动通过政策审核。
- [ ] 已确认外部发布平台中的频道映射、上传权限和可查询的远程任务状态。
- [ ] 已定义“谁可批准发布、谁可撤回、谁处理远程任务未知状态”。
- [ ] 已在不发布公开内容的前提下确认标题、描述、缩略图、计划发布时间和 AI 披露字段的操作路径。
- [ ] 已确定视频原始语言，并确认在哪里设置原始音轨语言、翻译标题 / 描述、字幕和多语言音轨。
  当前外部 Video API 与 DoodleStory 请求没有这些字段，不能把上传后的 YouTube Studio 人工步骤写成
  自动完成。详细差距见 [多语言与获利路径边界](language-and-monetization-boundaries.md)。

当前项目的发布调用边界、路径和任务状态说明见
[全量 API 调用清单](../../integrations/llm-agent-endpoints.md) 与
[视频发布平台文档归档](../../external-api/video-inboxlinks/README.md)。

## 2. 研究与事实来源

- [ ] 每个候选题目有来源账本：主张、来源、定位信息、访问日期、许可 / 使用备注和人工审核人。
- [ ] 史实 / 科学 / 数据类内容至少有两类独立的可靠来源；不能以另一支 YouTube 视频作为唯一事实来源。
- [ ] 明确哪些内容是事实、合理解释、争议观点或创作性表达；争议内容不伪装成确定事实。
- [ ] 已定义来源失效、网页变更、内容被删或证据不足时的停止规则。
- [ ] 对标频道只用于观察结构、节奏和受众问题；不下载、拼接或改写其脚本与素材。

## 3. 原创性、版权与平台合规

- [ ] 每条脚本有独立中心论点、原创旁白和自有视觉说明，避免可互换的批量模板。
- [ ] 每条已完成原创性账本：中心问题、独立论点、来源、与本频道近作的实质差异和人工审核人均可追溯。
  YouTube 的非真实内容规则按频道审查，不能只靠单条视频“换配图 / 换题名”判断为原创。
- [ ] 图像、字体、音乐、音效、地图、档案照片和第三方片段都有明确许可；无法确认的素材不进入成片。
- [ ] 已检查 YouTube 的[频道获利政策](https://support.google.com/youtube/answer/1311392?hl=en-AU)：重复、批量化、
  缺乏原创叙事 / 教育价值或通用 AI 模板的内容存在获利风险。
- [ ] 已检查 [AI 合成内容披露要求](https://support.google.com/youtube/answer/14328491?hl=en-PG)，为逼真或
  明显生成 / 改造的内容预留发布前披露判断，并保存“需要 / 不需要及原因”。非写实插画通常不需要该项
  披露；涉及真实人物、真实地点或真实事件的逼真重建时，必须由人工复核，不能由模型默认跳过。
- [ ] 若制作 1–3 分钟 Shorts，已确认所有音乐和其他第三方音频不会产生有效 Content ID claim；YouTube
  说明该时长的 Short 有有效 claim 时会被全球屏蔽，不能把“先发后处理”当作默认流程。
  ([YouTube Help](https://support.google.com/youtube/answer/15424877))
- [ ] 已排除新闻、医疗、金融、法律建议、未授权真人隐私、儿童敏感内容、危险行为和误导性逼真事件等
  高风险题材，除非另有专业审核和明确授权。

## 4. 媒体生产可行性

- [ ] 确认本赛道是否真的适合“静态插画 + 原创旁白 + 字幕”的叙事，而不是依赖实拍、屏幕录制、
  高频角色动画、音乐版权或复杂地图交互。
- [ ] 已先选择 **普通视频或 Shorts**，并把选择、理由和平台分类规则写进实验文件；方形 / 竖屏且最长
  3 分钟的视频会被归为 Shorts，若要保留普通视频形态应使用 16:9 等宽画幅。
  ([YouTube Help](https://support.google.com/youtube/answer/15424877))
- [ ] 选定画幅、目标时长、画面数量、旁白速度、字幕密度与封面风格；首轮不要同时测试这些变量，也
  不把 Shorts 与普通视频放进同一比较组。
- [ ] 对一条代表性脚本完成本地无发布渲染检查：图片比例、角色一致性、语音自然度、字幕时轴、输出时长、
  文件大小和画面文字可读性。
- [ ] 定义图像 / 语音 / 字幕 / 视频失败时允许重跑的局部步骤与成本上限。
- [ ] 为每个 Provider 准备可操作的异常处理人；不要在 Run 内静默切换未批准的模型或供应商。

## 5. 数据回流与实验纪律

- [ ] 确认数据来源：YouTube Studio、发布平台分析 API 或人工导出；标明哪些数据当前尚未自动接入。
- [ ] 发布前为每轮实验写预测、固定变量、唯一主动变量、检查点和停止条件。
- [ ] 首批实验固定一个原始语言；自动配音、自有第二音轨或多语言频道只能作为后续独立变量。
- [ ] 若启用 YouTube 自动配音，已开启发布前人工审核，并指定能审核目标语言的人；人名、地名、年代、
  数字、因果限定词和史料不确定性必须逐项检查。
- [ ] 所有内容最少记录：发布时间、标题、时长、播放、平均观看时长、平均观看比例、评论、订阅变化与
  限制备注。
- [ ] 普通视频另记录：封面、展示、点击率、30 秒 intro 与留存峰谷；数据不足时只记录，不判输赢。
- [ ] Shorts 另记录：engaged views、`Stayed to watch` 与 swiped away；不能用普通视频 CTR 代替。
  Shorts 不能像普通视频一样上传自定义缩略图，只能选择视频帧用于部分位置。
  ([YouTube Analytics](https://support.google.com/youtube/answer/12220281))
  ([YouTube thumbnails](https://support.google.com/youtube/answer/72431))
- [ ] 只有同一机制的多次独立证据才能升级为候选规则；单次表现不能直接修改 Skill。
- [ ] YPP 普通视频观看小时、Shorts 有效观看和收入均不作为第一轮内容机制的替代指标；Shorts Feed
  观看小时不能计入普通视频 4,000 小时路径。
- [ ] 数据回流、偏差诊断与下一轮只改变一个主要变量的规则，遵循仓库的
  [内容迭代实验周期模板](../../experiments/content-iteration-cycle-template.md)。

## 6. 成本与运营责任

- [ ] 写下每条视频的模型、图像、TTS、渲染、存储和人工审核成本上限。
- [ ] 设定日 / 周制作上限与人工审核容量；不因自动化而跳过审核。
- [ ] 指定异常、版权投诉、事实纠错、评论风险和发布事故的负责人及响应时限。
- [ ] 先运行少量真实样本，再讨论多账号、定时批量生产、分布式队列或自动策略升级。

## 就绪判定

| 判定 | 条件 | 下一步 |
| --- | --- | --- |
| 未就绪 | 频道定位、权限、来源账本或发布责任缺一项。 | 先补齐运营输入，不进入开发。 |
| 可做研究 Sprint | 有目标语言、频道 / 对标输入和来源审核人，但尚未准备生产。 | 实现或人工执行“研究 → 报告 → 3 个选题 → Gate”。 |
| 可做制作验证 | 研究结论已批准，媒体格式 / 成本 / 人工审核路径已确认。 | 做小样本制作，仍不自动发布。 |
| 可做真实实验 | 发布确认、数据回流和停止条件均已准备。 | 按单变量计划发布少量内容并复盘。 |
