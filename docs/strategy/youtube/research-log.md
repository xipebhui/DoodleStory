# YouTube 持续研究日志

用途：按日期记录影响赛道选择、实验设计或平台风险判断的新增证据。每条记录必须区分事实、推断与
未知项；单次资料或单个频道样本不能升级为长期策略规则。

## 2026-08-02：首轮实验的指标与节奏约束

### 新证据

- YouTube 说明，视频级受众留存通常需要 1–2 天处理；关键留存报告适用于至少 60 秒、且已有约
  100 次观看的视频。报告会标出 30 秒后的 intro、峰值和低谷，并可与相近长度的近期视频对比。
  ([Measure key moments for audience retention](https://support.google.com/youtube/answer/9314415?hl=en-11))
- CTR 和展示量应结合流量来源与受众阶段解释。高 CTR 或高平均观看时长本身并不保证展示增长；
  在同一条视频上同时试多个标题或缩略图也难以得到可比较结论。
  ([Decoding CTR & impressions](https://support.google.com/youtube/answer/16767369?hl=en))
- YouTube 表示，发布时点并不已知会影响视频长期表现，且增长并不与上传间隔存在关联；质量和对受众的
  理解优先于为频率而频率。([YouTube performance FAQ](https://support.google.com/youtube/answer/141805?hl=en))

### 对当前验证包的影响

- 维持“原创插画历史微纪录片”为首轮待验证方向；本次证据不改变赛道排序。
- 取消把 2 小时数据当作早期成败信号的做法；2 小时仅记录分发起点，72 小时后才做初步相对比较。
- 对于达到数据门槛的 90–180 秒视频，优先比较 30 秒 intro、平均观看比例、峰值 / 低谷以及
  同长度历史视频的典型留存，而不是只看播放和 CTR。
- 把发布时间固定为实验控制变量，但不将“黄金发布时间”作为策略假设；首轮也不为追求频率而压缩
  来源审核或视觉质量。

### 仍未知 / 不升级为规则

- 尚无目标频道、语言、题目和真实数据，不能设定适用于该赛道的绝对 CTR、留存或播放阈值。
- 尚未证明 90–180 秒是否为最佳时长；它只是当前静态插画旁白模板的待验证生产假设。
- 尚未形成“历史日常制度题优于技术 / 决策题”的结论，至少需要同一机制的多次独立发布证据。

### 下一次研究问题

在确定目标语言后，选定 3 个格式观察频道，比较其近作中“单问题标题、时长、描述来源提示和评论中的
具体提问”，再决定第一批 6 条候选题目的来源账本要求。

## 2026-08-02：原创性与合成内容披露是流程 Gate，不是文案备注

### 新证据

- YouTube 的频道获利政策说明，创作者内容应当是原创且“真实”的；重复、批量生产、通用、缺少实质
 变化或以获取观看为唯一目的的内容存在获利风险。政策自 2025-07-15 起将原“重复内容”更明确地称为
  “非真实内容”，并明确举例指出：没有创作者原创观点或洞察的通用 AI 模板内容不符合要求。审查可查看
  频道主题、最新 / 高观看视频、观看时长占比、标题、缩略图、描述和 About，而不是只判断单条视频。
  ([YouTube Channel Monetisation Policies](https://support.google.com/youtube/answer/1311392?hl=en))
- YouTube 要求披露“看似真实”的重大合成或改造内容，例如伪造真人言行、改变真实事件 / 地点影像、
  或生成未发生的逼真场景；非写实动画、一般脚本 / 字幕辅助和小幅美化通常不在该披露要求内。披露本身
  不会限制受众或获利资格，但持续不披露可能导致标签、内容移除或 YPP 处罚。
  ([Disclosing use of altered or synthetic content](https://support.google.com/youtube/answer/14328491))
- 对两个公开格式观察样本，频道自身均将内容定位为动画历史解释：
  [Simple History](https://www.youtube.com/@Simplehistory) 明确以动画呈现历史生活、文化、技术和事件；
  [The Armchair Historian](https://www.youtube.com/@TheArmchairHistorian) 明确以教育性、娱乐性的动画历史视频
  为定位。后者公开检索快照列出的新近标题以战争、帝国和政治事件为主，说明其题材重心与我们拟测的“日常制度 /
  技术机制”并不相同。它们只能用于观察“旁白 + 图解 / 动画”的格式可行性，不能证明首轮题目会有效，
  更不能作为脚本、画面或标题复刻来源。

### 对当前验证包的影响

- 保持“原创插画历史微纪录片 / 历史机制解释”为首轮待验证方向，但将“每条具有独立中心问题、可审计
  来源账本和自己的解释角度”升为进入脚本 Gate 的必要条件，而不是质量加分项。
- 将“原创性账本”加入后续 Agent 的持久化 Artifact：至少记录中心问题、主张、使用来源、与本频道
  最近内容的实质差异，以及人工审核人。它用于防止批量模板化，不用于证明频道一定能获利。
- 发布 Gate 增加一个可解释的 `AI 披露判断`：区分非写实插画、一般生产辅助与逼真 / 重大合成画面；
  需要披露时由人工在上传流程确认，不能让模型静默猜测或默认跳过。
- 对标研究改为两个层次：先用频道公开页记录格式线索；等目标语言确定、项目 API 凭据和频道标识准备好后，
  再使用项目的只读 `inspect_youtube_channel` 对 3 个目标频道做可复核研究卡。当前没有调用该项目 Tool，也没有下载或使用
  第三方素材。

### 仍未知 / 不升级为规则

- 政策说明的是频道合规与获利资格边界，不给出“原创性账本能提高观看或获利”的因果结论。
- 公开频道页不能可靠提供每条视频的留存、流量来源、制作成本、标题 / 封面迭代史或受众结构；它们不能
  代替获得授权后的只读频道研究和真实发布数据。
- 未确定目标语言、地区与频道基线，不能把英语动画历史频道的题材、节奏或产能迁移为我们的策略规则。

### 下一次研究问题

围绕“古代城市如何解决一个具体日常限制”建立 3 个候选题目的双来源账本，逐项检查中心问题、争议点、
可画场景、版权边界和是否涉及逼真历史重建；只保留能通过来源和原创性 Gate 的题目。

## 2026-08-02：三个候选历史题完成双来源初查

### 新证据

- 罗马粮食题由 Ostia Antica 遗址管理机构、Portus Project 和 Cambridge 学术专著章节交叉支持：
  大型海船、港口换装、Tiber 河船、搬运计量、仓储与本地面包房构成可追踪的系统；同时不能把它
  简化为所有粮食只有一条路线或完全由国家单独经营。
- 罗马供水题由 Frontinus 同时代管理文本、National Geographic Education 和 The Met 教育资料交叉支持：
  重力只是流动机制，分水、不同用途、水质、维护、渗漏和非法引水共同决定系统运行；不能据此宣称
  每户都有自来水或采用有争议的精确流量换算。
- 摩亨佐-达罗题由 UNESCO 遗址说明和 British Museum 馆藏说明交叉支持：城市网格、井、洗浴和排水
  是可靠物证，但遗址仅部分发掘、文字未释读，不能从排水设施直接推出确定的统治或宗教结构。

完整来源、可画链路和停止条件见
[候选题来源账本](candidate-topic-source-ledgers.md)。

### 对当前验证包的影响

- 三题当前排序为：罗马港口粮食供应 → 罗马城市供水 → 摩亨佐-达罗排水。
- 排序依据是来源完整度、可视化和过度推断风险，不是市场或播放预测。
- “两个来源”不再只按链接数量判断；后续必须检查来源是否为不同证据类型、是否只是相互转述，以及
  它们明确不能支持哪些表述。

### 仍未知 / 不升级为规则

- 尚未写脚本、生成样片或发布，不能判断三题的标题点击、留存、讨论或成本。
- 首批候选题不能证明“古代城市系统题”优于历史人物、神话或其他内容。

## 2026-08-02：公开频道只能提供格式参照，不能给出胜负

### 新证据

- History Matters 的公开标题高度集中于一个 `Why / When` 问题，可作为“单条只解决一个问题”的包装参照。
- The Armchair Historian 的公开长视频描述可见一手史料、书目和团队署名，适合作为来源与制作信用参照；
  其长时长、连续动画和团队规模不适合作为当前产能基准。
- Simple History 同时覆盖比较、事实列表、生活、技术和事件等多种结构，说明视觉历史并不只有一种包装；
  但首批六条若混用这些结构，就无法验证单一题型假设。

完整观察见
[格式观察、平台分流与相邻赛道压力测试](format-and-adjacent-lane-review.md)。

### 对当前验证包的影响

- 首批统一为单一因果问题，不复制 `Short Animated Documentary` 等固定后缀。
- 描述区最少包含中心论点、两类来源、史料不确定性、制作署名和适用时的 AI 披露说明。
- 公开频道页没有留存、流量来源、成本、受众和标题测试史，不能写“某格式表现最好”。

## 2026-08-02：普通视频与 Shorts 必须分开设计实验

### 新证据

- YouTube 说明，2024-10-15 后上传的方形或竖屏、最长 3 分钟视频会被归为 Shorts；使用 16:9 等
  宽画幅可避免这一分类。([Three-minute Shorts](https://support.google.com/youtube/answer/15424877))
- Shorts 不能像普通视频一样上传自定义缩略图，只能选择一帧用于搜索、频道页等部分位置。
  ([Custom thumbnails](https://support.google.com/youtube/answer/72431))
- Shorts 的专属指标包括 engaged views 和 `Stayed to watch`；平均观看时长、平均观看比例按 engaged
  views 对应观看时长计算。([Content performance](https://support.google.com/youtube/answer/12220281))
- 1–3 分钟 Short 有有效 Content ID claim 时会被全球屏蔽，因此背景音乐许可是发布前硬 Gate。

### 对当前验证包的影响

- 修正原“3:4、90–180 秒与普通 CTR / 缩略图指标并用”的错误。
- 默认建议改为 16:9、90–180 秒普通视频，以保持小规模生产假设和普通视频分析能力；时长仍未验证。
- 如果频道选择 Shorts，则六条全部采用同一 Shorts 规格，使用 Shorts 指标，另开实验，不与普通视频混比。

### 仍未知 / 不升级为规则

- 尚未证明普通视频优于 Shorts；默认只是为了与当前研究问题和公开格式参照保持一致。
- 尚未验证 DoodleStory 的 16:9 历史画面、字幕密度和独立缩略图质量，进入制作前必须本地渲染。

## 2026-08-02：相邻赛道压力测试没有改变首选方向

### 新证据与推断

- 历史助眠的公开样本常见 1.5–3 小时、章节化慢旁白和大量静态视觉，表面适配当前媒体形态；但当前
  项目真实 Remotion smoke 仅约 24.7 秒，并已暴露重复 TTS、缺少图片检查和完成状态错误，超长视频
  会放大长任务恢复、字幕、存储、版权和成本风险。
- 神话与民俗仍有高视觉适配，但必须区分公版母题与受版权保护的现代译本 / 改编，也要处理宗教文化语境。
- 城市 / 地理系统可先作为历史题内的港口、供水、道路等子类型；现代地图、统计和地缘题需要独立能力。
- AI 写实历史重建会让未经证实的服饰、建筑和事件细节看似事实。YouTube 要求对逼真、实际未发生的
  合成场景进行披露；首轮用非写实解释性插画更容易保留“证据 / 示意”边界。

### 对当前验证包的影响

- 保持历史机制解释为首选，神话民俗为备选 A，城市 / 地理为赛道内子题或备选 B。
- 历史助眠降为后续独立的音频优先实验；在长任务恢复和单位小时成本未验证前，不进入首轮。
- 全动画军事史和写实历史重建不作为第一批生产形态。

### 下一次研究问题

在用户下一次明确启动研究时，优先补齐另外三个候选题来源账本，并根据已选择的目标语言与内容类型，
建立普通视频或 Shorts 的发布前预测模板。当前不设每日或后台自动研究任务。

- 六题暂分为流动网络、水与季节、城市风险三组，每组两个独立题；完整矩阵见

### 仍未知 / 不升级为规则

- 同组两题跨越不同文明、年代与受众熟悉度，不能把发布差异严格归因于机制组。
- 吴哥水网和摩亨佐-达罗排水的地图、用途和治理不确定性更高，必须先通过研究 brief 才能进入脚本。
- 没有真实发布，候选排序不进入 `strategy_memory.md`。

## 2026-08-02：YouTube 支持多语言，但当前发布链路尚未接入

### 新证据

- YouTube Studio 支持翻译标题 / 描述；符合条件的频道可使用自动配音，部分具有 Advanced features 的
  创作者可上传自有多语言音轨。官方提醒自动配音可能误读发音、专名、习语和术语，可配置发布前人工审核。
  ([Automatic dubbing](https://support.google.com/youtube/answer/15569972))
  ([Multi-language features](https://support.google.com/youtube/answer/13338784))
- YouTube Data API 的 `videos` 资源提供 `snippet.defaultLanguage`、`snippet.defaultAudioLanguage` 和
  `localizations` 元数据。([YouTube Data API](https://developers.google.com/youtube/v3/docs/videos))
- 本地归档的外部 Video API 上传请求只有标题、描述、标签、可见性、儿童内容、合成媒体、付费推广、
  订阅通知、封面和视频 URL；DoodleStory `_create_payload()` 也没有语言、localizations、字幕或第二音轨。

### 对当前验证包的影响

- 首批六条固定一个原始语言；多语言是后续独立变量，不同时建立多个语言频道。
- 当前上传后需要在 YouTube Studio 人工设置语言和管理配音，不能在 Agent 流程里标记为自动完成。
- 历史专名和不确定性限定词需要目标语言审核人；自动配音不得默认全部发布。
- 完整能力分层见 [language-and-monetization-boundaries.md](language-and-monetization-boundaries.md)。

### 仍未知 / 不升级为规则

- 尚未确定原始语言，也没有多地区受众数据，不能判断英语、中文或任何第二语言更优。
- 没有真实配音样本，不能判断 YouTube 自动配音对历史内容的可用性和成本节省。
- 外部 Video API 将来是否增加语言或音轨字段未知；文档与 smoke 出现前只记录缺口。

## 2026-08-02：YPP 普通视频与 Shorts 是独立资格路径

### 新证据

- 扩展 YPP 的早期门槛为 500 订阅者、近 90 天 3 个有效公开上传，并满足近 12 个月 3,000 有效公开
  观看小时或近 90 天 300 万有效公开 Shorts 观看；这一层主要开放粉丝资助和部分 Shopping。
- 广告与 YouTube Premium 分成门槛为 1,000 订阅者，并满足近 12 个月 4,000 有效公开观看小时或
  近 90 天 1,000 万有效公开 Shorts 观看。Shorts Feed 观看小时不计入 4,000 小时。
  ([Expanded YPP](https://support.google.com/youtube/answer/13429240))
  ([YPP overview](https://support.google.com/youtube/answer/72851))
- Watch Page 与 Shorts Feed 使用不同收益模块和计算方式，不能只比较 55% 与 45% 的表面比例。
  ([Partner earnings](https://support.google.com/youtube/answer/72902))

### 对当前验证包的影响

- 维持 16:9、90–180 秒普通视频作为低成本内容机制实验，不把 YPP 作为首轮成功标准。
- 若机制出现重复正向信号，下一轮才把视频长度作为唯一主要变量，验证较长普通视频；当前不直接延长。
- 不使用“Shorts 更快获利”或“普通视频每次观看更值钱”等未经真实频道数据支持的结论。
