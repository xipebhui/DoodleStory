# YouTube 新赛道 Agent 流程设计模板

用途：在开发一个新 YouTube 赛道 Agent 前，先把业务目标、可用 Tool、持久化产物、人工确认和
验收方式写清。本模板描述设计约束，不创建任何代码或 Skill。

## 0. 基本信息

```yaml
flow_name: ""
owner: ""
target_language_and_region: ""
target_channel: ""
one_sentence_outcome: ""
non_goal: ""
planned_sprint: ""
```

## 1. 输入合同

| 输入 | 必填 | 允许来源 | 校验 / 拒绝条件 |
| --- | --- | --- | --- |
| 赛道问题 | 是 | 用户、已批准的策略 Artifact | 不能只写“做爆款”；必须可研究。 |
| 对标频道 / 视频 | 视流程而定 | 用户 URL、频道别名 | 不允许把未授权素材直接作为复刻输入。 |
| 目标账号 | 是 | 已登记频道 | 必须有 owner / 管理权限与明确定位。 |
| 内容来源 | 是 | 来源账本 | 每个事实 / 引文都可追溯，证据不足则停止。 |
| 预算与时长 | 是 | 用户确认 | 超过上限前等待确认。 |

## 2. Skill 合同

```text
目标：
  这个 Skill 最终替用户产出什么可检查的结果？

方法：
  研究、推理和创作的顺序；哪些结论必须引用证据。

允许 Tool：
  只写当前任务真正需要的 Tool 名称。

禁止：
  例如自动发布、复制第三方脚本、无来源的事实断言、跳过人工确认。

完成条件：
  哪些 Artifact / Gate 必须存在，才能让 Run 结束或进入下一阶段。
```

Skill 的版本必须随 Native Agent Run 固定。修改规则后应产生新版本，不能影响正在执行或等待确认的
Run。

## 3. Tool 设计表

每个 Tool 只承担一个原子、可审计的动作。能复用的优先复用：

| Tool | 用途 | 输入 | 成功输出 | 副作用 / 幂等键 | 失败时的可见结果 |
| --- | --- | --- | --- | --- | --- |
| `inspect_youtube_channel` | 频道研究 | 频道标识 | 结构化洞察与素材引用 | 只读；Run / 调用记录 | 来源不可用、返回不完整、频道不匹配。 |
| `get_account_creation_context` | 读取已登记账号上下文 | 账号别名 | 定位、对标、近作摘要 | 只读 | 多个候选或权限不足。 |
| 新 Tool：`<name>` | `<single purpose>` | `<schema>` | `<stable artifact/reference>` | `<Tool Call ID / external id>` | `<operator action>` |

禁止让模型直接调用未记录的 HTTP 地址。外部副作用必须由后端 Tool 发起，保存调用状态、外部 ID、
产物引用与错误信息。

## 4. Artifact 设计

| Artifact | 最小字段 | 谁创建 | 谁审核 | 保留目的 |
| --- | --- | --- | --- | --- |
| 研究卡 | 频道、观察窗口、证据链接、结论、未知项 | 研究 Tool / Agent | 人工 | 避免把对标印象当事实。 |
| 来源账本 | 事实、来源、摘录 / 定位、许可备注、审核状态 | Agent + 人工 | 人工 | 事实、版权与更新追溯。 |
| 赛道策略 | 受众、内容承诺、候选题目、预测、风险 | Agent | 人工 | 固定本轮假设。 |
| 原创性账本 | 中心问题、独立论点、使用来源、与近作的实质差异、审核人 | Agent + 人工 | 人工 | 防止批量模板化；不以它承诺获利。 |
| 脚本 | 中心论点、场景、旁白、来源引用 | Agent | 人工 | 原创性和事实审核。 |
| 视觉方案 | 分镜、人物 / 场景锚点、避免项、画幅 | Agent | 人工 | 保证图片承担解释功能。 |
| 成片 | 视频、字幕、封面、描述、AI 披露判断及理由 | 媒体 Tool | 人工 | 发布前检查。 |
| 发布记录 | 频道、远程任务 ID、公开视频 ID、时间 | 发布 Tool | 人工 | 外部副作用追踪和数据回流。 |

## 5. Gate 设计

每一个费用较高、可公开传播或不可逆的动作前设置 Gate。Gate 的决定必须来自后端的 owner、
`allowed_actions` 与 `state_version`，而不是前端猜测。

| Gate | 进入条件 | 允许决定 | 通过后的下一步 |
| --- | --- | --- | --- |
| 研究 Gate | 研究卡、来源账本和原创性账本完整 | 批准 / 要求补证 / 停止 | 形成赛道策略。 |
| 策略 Gate | 目标、预测、固定变量与唯一测试变量明确 | 批准 / 修改 | 生成候选脚本。 |
| 脚本 / 事实 Gate | 有中心论点、来源、风险备注 | 批准 / 退回 | 生成视觉方案。 |
| 视觉 / 媒体 Gate | 画面、旁白、字幕、视频均可预览 | 批准 / 重跑局部步骤 | 登记可发布视频。 |
| 发布 Gate | 频道、标题、描述、AI 披露判断及理由、可发布视频和计划时间明确 | 明确确认 / 取消 | 创建远程上传任务。 |

## 6. 状态、失败与恢复

- 首选当前 Native / Durable Runtime；复用 Run、Step、Event、Artifact、Approval、Tool Effect 和
  控制命令，不另建第二套任务状态机。
- 研究失败、事实审核退回、媒体失败、远程发布状态未知是不同故障；它们必须分别显示给用户。
- 外部提交后状态不明时，标记为 `unknown effect` 并等待人工处理；不能因重试而重复发布。
- 刷新页面和 SSE 断线后重新读取后端投影。不得依赖浏览器内存判断 Run 是否完成。

## 7. 发布后实验合同

```yaml
hypothesis: ""
fixed_variables: []
single_changed_variable: ""
review_checkpoints: ["2h", "24h", "72h"]
metrics: []
stop_condition: ""
rule_upgrade_threshold: "同类独立证据至少 3 次"
```

没有发布前预测，只能记录发布数据，不能做“策略验证成功 / 失败”的复盘。单次高播放或低播放只能
记录观察，不能自动修改 Skill。

## 8. 验收清单

- [ ] 输入、来源和版权边界明确。
- [ ] 每条有独立中心问题、论点和原创性账本；不能以仅换题名 / 配图的模板批量通过。
- [ ] Skill 版本、可用 Tool 与禁止动作明确。
- [ ] 每个 Tool 有输入、输出、幂等和失败语义。
- [ ] 中间结论以 Artifact 保存，而非只在聊天中出现。
- [ ] 费用、公开发布和不可逆动作前有 Gate。
- [ ] 有 owner 校验、取消、恢复和未知副作用处理方式。
- [ ] 有发布前预测、数据回流与停止条件。
- [ ] 有最小真实链路验收，不以模型回复看起来合理作为完成标准。
