# Paynes Creek G6 九镜串行生产协议

更新时间：2026-08-12

状态：Ready as design / not authorized / not run

适用范围：G5-B 写入 `pass_for_remaining_image_plan` 之后，S02、S05–S12 的单图生产与验收

## 1. 决策

G6 不是“把剩余九张图一起生成”，而是九个连续、互相阻断的单图 Gate：

```text
G5-B pass_for_remaining_image_plan
  → G6-01 S02
  → G6-02 S08
  → G6-03 S11
  → G6-04 S05
  → G6-05 S09
  → G6-06 S07
  → G6-07 S06
  → G6-08 S10
  → G6-09 S12
  → 只开放 G7 语音与字幕计划评审
```

每个箭头只表示“允许评审下一次独立授权”，不表示自动执行。每个子 Gate 都必须单独复制空白 attempt、
核对授权与成本、创建一个 Run、生成一张候选、执行一次机器检查、完成事实与视觉人工复核、写终态并停止。

## 2. 为什么不按成片顺序生成

生产顺序按四个因素排序，而不是按 Scene ID 排序：

1. **依赖**：后镜是否需要前镜已经稳定的对象或视觉语法。
2. **视觉新颖度**：是否引入锚点图尚未覆盖的画面类型。
3. **事实漂移风险**：模型是否容易把“可能、未知、后来发生”画成确定事实。
4. **失败成本**：风险较高且相对独立的画面尽早验证，避免到最后才推翻整套视觉系统。

| Gate | Scene | 视觉族 | 主要风险 | 前序依赖 | 排位理由 |
| --- | --- | --- | --- | --- | --- |
| G6-01 | S02 | 抽象海岸地图 + 时间带 | 现代边界、精确古岸线、画面文字 | S01 地图锚点 | 低成本补齐地点 / 时段基线，并验证无文字时间带 |
| G6-02 | S08 | 单器物证据板 | 抄论文图、短桨替代、数字乱码 | S02；全体锚点 | 直接证据明确，先固定后续运输镜头的桨对象 |
| G6-03 | S11 | 现代环境剖面 | 把古人画在水下、把泥炭写成唯一原因 | S08；全体锚点 | 唯一的新环境视觉族，风险高且相对独立，提前失败最省成本 |
| G6-04 | S05 | 聚落平面 / 切面 | 编造家谱、性别、等级、同时存在 | S04 陶器 / 火候锚点 | 在建筑语法稳定后再建立生活—作业邻接关系 |
| G6-05 | S09 | 低细节独木舟 | 画出可数货物、船员、路线和目的地 | S08 船桨 | 复用已通过船桨对象，验证“可运输”不等于“有货单” |
| G6-06 | S07 | 散盐 / 可能盐饼比较 | 把可能盐饼画成货币或完好文物 | S04；S09 | 在运输语法后验证成品形态，但不补市场制度 |
| G6-07 | S06 | 重复证据分布图 | 虚构产量、110 座同时工厂、工业流水线 | S04、S05 | 需先稳定器物与作业空间，才能表达超出自用而不量化 |
| G6-08 | S10 | 海岸—内陆抽象网络 | 把方向关系闭合成具体路线、城市和买家 | S01、S02、S08、S09 | 依赖地图和运输视觉已通过，接近收束时再做抽象解释 |
| G6-09 | S12 | 五对象证据链 | 把开放链画成完整旅程或市场证明 | 全部前镜 | 最后综合，只能引用已通过对象，不在终镜发明新证据 |

成片仍按 S01–S12 播放；本表只控制资产生产和失败停止顺序。

## 3. 每个子 Gate 的固定副作用预算

一次明确授权只覆盖选中的一个 Profile：

| 项目 | 上限 |
| --- | ---: |
| 新 Run | 1 |
| `generate_image` Tool Call | 1 |
| 图片 Provider 请求 | 1 |
| 新候选图片 | 1 |
| `inspect_image` Tool Call | 1 |
| 事实人工复核 | 1 |
| 视觉人工复核 | 1 |
| 自动重试 / 第二候选 / 自动下一镜 | 0 |

`ask_user`、机器 `accept`、Provider 返回成功、文件可打开，都不能单独构成 Gate 通过。当前候选失败时保留
Run、Tool、Asset、错误与审核证据，写 `needs_revision` 或对应失败终态并停止；v02 必须使用新 attempt 与
新授权。

## 4. 共用前置检查

创建 Run 之前必须同时满足：

- G5-B 以及本 Profile 列出的所有 G6 前序 Gate 已有真实、可回查的通过记录。
- 授权精确到一个 Gate / Scene，记录授权人、时间、引用和单次成本上限。
- 事实审核人、视觉审核人已指定，且不是用机器 verdict 代替。
- 从当前 Prompt 包重新提取规范 Prompt，SHA-256 与 Profile 完全相同。
- 重新解析专用 Style；名称、状态、模型、比例、Prompt 哈希、参考图数与 Profile 要求一致。
- Native Skill 中只有 `generate_image` 与 `inspect_image`，当前 Provider / route 与已批准锚点一致。
- 所有前序 approved 图片存在，真实像素尺寸已记录且完全一致。
- attempt 文件是从空白模板新复制的独立记录，不覆盖旧 attempt。

任一项缺失写 `blocked_precondition`，不创建 Run。协议不授权自动修复 Style、切换 Provider、修改 Prompt、
缩放图片或绕过前序 Gate。

## 5. 共用机器与人工门槛

### 机器检查

- 请求的 `image_id` 必须等于本 attempt 的候选图片 ID。
- `checks`、`expected.story_beat`、`characters` 和 `required_text` 必须逐字匹配选中 Profile。
- `checks` 为 1–10 个不重复的稳定 ID；`required_text` 始终为空，因为本片不让图片模型生成文字。
- 只有 `inspect_image.response.verdict == accept` 才能进入人工复核；技术失败不允许跳过机器检查。

### 共用事实复核

- 唯一主张、证据等级、允许项和禁止项与证据板一致。
- 未把 B 级解释或 A+B 证据链画成直接出土记录。
- 未复制来源论文图、第三方照片、地图排版或文物展示构图。
- 未增加买家、价格、货单、家谱、精确产量、古代边界或完整旅程等来源未支持信息。

### 共用视觉复核

- 候选真实宽高与所有 approved 前序图完全相同；只满足 Remotion 的 `0.01` 比例容差仍不通过。
- 核心对象位于中央 84% 与上方 70%，底部 30% 留给中文字幕。
- 使用选中 Profile 的真实运动探针后，唯一对象、断口和关键关系仍完整可辨。
- 色板、平面编辑插画、对象轮廓和证据强度语言与已批准锚点连续。
- 视频观看尺寸下仍能识别唯一主张，不依靠画面文字解释。
- 无文字、字母、数字、标签、Logo、水印、乱码或明显生成伪影。

三类 verdict 全部通过，才能把 `PC-Sxx-v01.png` 复制 / 命名为 Profile 指定的
`PC-Sxx-approved.png`；文件名本身不构成通过证据。

## 6. 九镜单一验证问题与事实边界

### G6-01 / S02：时间与地点

**唯一问题**：能否在不生成文字、日期、现代国界或精确古岸线的前提下，让抽象海岸与宽时间带承载
“今天伯利兹南部 / 公元六百至九百年”这一旁白基线？

通过时必须看到简化海岸、近似泻湖和无标签宽时间带；不得出现地图标签、国旗、政治边界、精确遗址点、
卫星底图或把当前海岸线宣称为古代实测岸线。`static` 探针要求原图全程安全。

### G6-02 / S08：全尺寸木桨

**唯一问题**：能否用原创几何对象板呈现一支完整船桨和“可测量的全尺寸对象”，同时不复制论文图、不
替换成搅拌桨，也不让图片模型生成数字？

一米四三由旁白 / 字幕陈述。画面只保留无标签全长线和无标签圆形轴径剖面；不得出现 `1.43`、`5 cm`、
标尺刻度文字、短桨、装饰纹、博物馆展柜、船员、货物或具体运输记录。`zoom_out` 从 `1.08 → 1.00`，
起始裁切与末帧全图都需安全。

### G6-03 / S11：后来被淹没与保存

**唯一问题**：能否在同一环境切面中区分今天的浅水线、沉积 / 泥炭、被保存木柱与古地面，而不把古人
画成在水下煮盐，也不把缺氧泥炭说成唯一保存原因？

允许现代调查旗标或低细节研究者；禁止深海、潜水寻宝、古代水下工人、完整海底工厂或“只有泥炭导致
保存”的排他性因果。`pan_down` 从 `translateY(-3%) → 3%`，上下端都必须保留水线、沉积层和木柱关系。

### G6-04 / S05：居住空间与盐厨房相邻

**唯一问题**：能否用平面 / 切面混合图表达两个功能空间相邻，并保留“家庭或亲属群体参与”的有限解释，
而不编造具体家谱、性别、等级和分工？

生活空间用普通容器，盐厨房用火塘、粗陶与支座；最多两名中性低细节人物。不得声称所有建筑同时存在，
不得出现宫殿、专业工厂等级、家谱线或性别化岗位。`pan_down` 两端都要看清邻接边界和两类对象。

### G6-05 / S09：独木舟可行但没有货单

**唯一问题**：能否让船桨、水面运动和低细节独木舟支持运输可行性，同时让艇内形状不可计数、路线与
目的地保持未知？

不得画出可数盐饼、载重数字、明确船员、码头、地图路线、目的城市、买家或货单；琥珀断续尾迹只能表示
运动解释。`pan_right` 从 `translateX(-3%) → 3%`，独木舟、桨和开放水域两端都不可裁掉。

### G6-06 / S07：散盐与可能盐饼

**唯一问题**：能否让左侧散盐与容器保持确定，让右侧仅一块朴素盐块保持“可能”状态，而不被读成货币、
标准商品或完好出土文物？

右侧可能盐块只占约三分之一，用不闭合琥珀虚线表示解释；禁止钱币、币纹、面额、品牌、市场摊位、价格、
成堆可数盐饼和博物馆式完好文物。`static` 探针要求比较关系全程安全。

### G6-07 / S06：超过日常自用但不量化

**唯一问题**：能否通过重复粗陶碎片、柱位和专门作业空间表达“超过偶尔家庭自用”，同时不发明年产量、
工厂数量或同时运行规模？

重复证据必须是分布与累积，不是工业流水线；禁止数字图表、`110` 座同时工厂、吨 / 年、库存、统一工位、
烟囱或大规模同时劳作场景。`zoom_out` 的起始和末帧都要保留重复证据与作业空间关系。

### G6-08 / S10：内陆方向网络不是确定路线

**唯一问题**：能否把海岸节点、未命名内陆方向和三条中途断开的解释线组织成网络，而不闭合具体路线、
城市、买家或价格？

只允许一个海岸节点、若干未命名内陆节点和中部断口；禁止河名、城市名、行政边界、完整道路、箭头到达、
买家、市场、价格、货量或“全国供应”结论。`static` 下断口必须在视频尺寸仍清晰。

### G6-09 / S12：机制链可以拼出，单次旅程不能

**唯一问题**：能否只用已经通过的五类对象拼成“浓缩—煮卤—成盐—水运—内陆联系”的证据链，同时让
最后一段保持开放，拒绝补出某船盐的完整旅程？

五对象必须分别复用已通过漏斗 / 收集罐、陶器 / 火候、散盐 / 可能盐饼、船桨、海岸—内陆节点语言；
直接证据用实线，解释用断线，末段必须开口。禁止新增买家、目的地、船货单、价格、钱币、市场验证或闭环。
`zoom_out` 起始与末帧都要保留五对象和最终断口。

## 7. 尺寸与运动探针

| Preset | 当前运行时事实 | 必查状态 |
| --- | --- | --- |
| `static` | `scale(1)`，无平移 | 原图 |
| `zoom_out` | `scale(1.08) → scale(1)`，原点 `center center` | 起始裁切 + 末帧全图 |
| `pan_right` | `scale(1.08)`，`translateX(-3%) → translateX(3%)` | 左端 + 右端 |
| `pan_down` | `scale(1.08)`，`translateY(-3%) → translateY(3%)` | 上端 + 下端 |

实现来源为 `remotion/src/NarratedPanels.tsx`。当前没有按对象设置变换原点、关键帧或自定义平移幅度的能力。
若探针不能实现创作意图，记录 `motion_capability_mismatch` 并停止；不能在当前 attempt 偷改 motion、Prompt
或代码。

当前 Remotion 仅在图片宽高比差大于 `0.01` 时拒绝，但本片采用更严格门槛：九镜的真实像素宽高分别与
S03、S01、S04 以及所有已通过 G6 前序图完全相同。不同尺寸不得在当前 attempt 内缩放、补边、裁切或
重采样。

| G6-04 / S05 | `pass_for_g6_05_s09` | G6-05 / S09 |
| G6-05 / S09 | `pass_for_g6_06_s07` | G6-06 / S07 |

| G6-09 / S12 | `pass_for_g7_audio_subtitle_plan_review` | G7 计划与授权评审 |

共用失败终态：

- `blocked_precondition`：前序、授权、成本、审核人、Prompt、Style、尺寸基线或 Profile 不完整；不创建 Run。
- `failed_before_image`：Run 在图片 Tool 前失败；保留 Run，新 attempt 另行授权。
- `failed_during_image`：图片调用或资产失败；不补第二张。
- `failed_during_inspection`：VL 技术失败；不跳过机器检查。
- `needs_revision`：机器非 `accept`、尺寸 / 运动失败或任一人工非 `pass`；记录首个失败项并停止。

任何通过状态都要求机器 `accept`、事实 `pass`、视觉 `pass` 同时成立，并与选中 Profile 的 `pass_status`
完全一致。`next_allowed_gate_review` 只开放评审，不授权自动执行。

## 9. 证据记录

执行时复制[空白 attempt 模板](paynes-creek-g6-scene-attempt-template.json)，按 Gate、Scene、日期和 attempt
命名，例如 `paynes-creek-g6-02-s08-2026-08-12-attempt-01.json`。九镜使用九个独立文件，旧记录不覆盖。

未运行写 `not_run`，未审核写 `not_reviewed`，未知写 `null`。真实宽高、哈希、调用次数、成本和 verdict
必须来自持久化记录或真实文件；不得记录 API Key、Authorization、签名 URL、账号密码或本地绝对数据库
路径。
