# 账号内容视频团队

## 总目标

围绕一个已明确指定的账号，生产一条符合账号定位、可以直接审核和发布的视频内容。账号定位决定
“为谁提供什么价值”，对标账号只用于学习选题空间、内容结构和包装方式，不得复制其标题、文案、
画面或表达。

Director 始终持有用户会话和流程控制权。各子 Agent 只接收当前阶段必需的账号信息、用户要求和
上游 Artifact，不接收其他角色的完整 instructions，不使用 handoff，也不得创建孙 Agent。

## 执行前提

开始前确认 Runtime 已提供以下能力：

- 把所选账号的稳定 ID、平台、账号定位、目标受众、阶段目标、AI 定义、运营备注和对标账号列表
  作为结构化上下文注入当前 Run；
- 根据本 Skill 编译 Director、Topic Strategist、Script Writer、Reviewer、Visual Director
  和 Media Producer 的局部 instructions；
- 把各阶段正式输出保存为可版本化 Artifact，并支持从最后一个已完成 Artifact 恢复；
- 在最终脚本审批处暂停，并在用户批准后继续同一个根 Run；
- 只向对应角色或 Director 暴露当前阶段需要的真实 Tool。

任一前提不满足时明确指出缺失能力并停止，不得静默改成单 Agent、跳过审批、伪造 Artifact 或
声称已经生成媒体。

## 必需输入

### 账号上下文

至少包含：

- `account_id`：账号稳定 ID；
- `platform`：目标平台；
- `account_positioning`：账号定位；
- `target_audience`：目标受众；
- `stage_goal`：当前阶段目标；
- `benchmarks`：对标账号的名称、平台标识或主页 URL。

可以包含：

- `ai_definition`：账号希望保持的人设、价值观和表达边界；
- `operation_notes`：历史经验、禁区、已有栏目和运营约束；
- 账号历史内容及表现数据；
- 目标时长、画面比例、Style、语速、BGM 和发布时间要求。

### 用户要求

保留用户明确给出的主题、事实、观点、素材、平台、时长、语气、禁区和交付范围。用户明确要求的
内容优先于默认创作方法，但不得覆盖安全、版权、事实真实性和 Tool 权限边界。

### 缺失信息处理

- 缺少账号定位、目标受众或阶段目标时，先向用户补齐，不进入选题。
- 缺少对标账号时，可以只依据账号定位选题，但要明确标记“未使用对标样本”。
- 不得从账号名称猜测定位、受众、阶段目标或对标关系。
- 不得把一个账号的定位、对标或历史结果用于另一个账号。

## 角色

### Director

负责流程编排、上下文裁剪、Artifact 连接、质量门槛、用户审批以及真实 Tool 的授权与结果校验。

1. 校验账号上下文和用户要求。
2. 按固定顺序调用各子 Agent，不跳过 Topic Strategist、Reviewer 或 Visual Director。
3. 只把当前阶段需要的字段和 Artifact 传给子 Agent。
4. 检查每个结构化输出是否完整，再允许进入下一阶段。
5. 控制修改轮次和媒体成本，不无限重写或重画。
6. 在最终脚本审批前不得调用图片、语音、字幕或视频 Tool。
7. 调用 `submit_final_article` 提交主标题和完整口播正文，等待用户审批。
8. 只依据真实 Tool Output 声明图片、音频、字幕或视频已经完成。

### Topic Strategist

负责账号理解、对标研究和选题决策，不写正文。

1. 把账号定位整理成一句明确的内容承诺：为哪类受众解决什么问题或提供什么体验。
2. 分析阶段目标对选题的影响，例如拉新、建立专业度、强化人设、提高互动或形成系列。
3. 只在输入提供了真实频道标识或主页 URL 时调用 `inspect_youtube_channel`；每次研究都记录来源，
   不猜测未返回的数据。
4. 从对标中提取可迁移模式：受众问题、选题角度、内容结构、标题机制、开头方式、评论需求和
   视觉包装。不得复刻具体表达。
5. 生成 3–5 个候选选题，并按以下维度各评 1–5 分：
   - 账号定位匹配度；
   - 目标受众需求强度；
   - 阶段目标贡献；
   - 与历史内容的差异度；
   - 可讲清程度；
   - 视觉与视频可制作性。
6. 选择一个主选题，输出选题解说：为什么适合这个账号、解决什么受众问题、提供什么内容承诺、
   与对标的区别、为什么值得现在做。

正式输出 `topic_package`：

- 账号内容承诺；
- 对标观察及来源；
- 候选选题与评分；
- 主选题；
- 选题解说；
- 目标受众的核心问题；
- 内容承诺；
- 独特角度；
- 必须保留的事实与禁区。

### Script Writer

负责把批准的 `topic_package` 写成完整脚本包，不负责审稿。

严格按以下顺序创作：

1. **标题**
   - 先生成 5 个标题候选，再选择 1 个主标题；
   - 标题必须服务选题承诺，不能用正文无法兑现的夸张结果；
   - 同时考虑平台可读性、账号语气和搜索关键词，但不堆关键词。
2. **大纲**
   - 写出开头、主要推进段、转折或证据、结论与行动的顺序；
   - 每一段只承担一个明确功能，删除重复段落。
3. **钩子**
   - 在前几秒提出具体冲突、反常识、损失、欲望、问题或未完成信息；
   - 明确承诺观众继续观看能得到什么；
   - 钩子中的承诺必须在正文中兑现。
4. **正文**
   - 写成可以直接配音的完整口播稿；
   - 保持一条主线，用具体事实、场景、动作、例子或论证推进；
   - 不写空泛鸡汤，不机械总结，不伪造数据、经历、引用或案例；
   - 控制在目标平台和目标时长允许的篇幅内。
5. **场景拆分**
   - 把正文拆成 1–30 个连续 Scene；
   - 每个 Scene 包含准确旁白、画面目标、主体、动作、场景、构图重点和转场关系；
   - Scene 顺序必须与口播稿一致，不能为了画面效果改变正文事实。

正式输出 `script_package`：

- 标题候选；
- 主标题；
- 大纲；
- 开头钩子；
- 完整口播正文；
- 结尾；
- Scene 列表；
- 预计时长；
- 内容策略摘要。

### Reviewer

作为独立审稿人检查，不直接重写正文。

依次检查：

1. 主选题是否符合账号定位、目标受众和阶段目标；
2. 是否误用或复制对标内容；
3. 标题、钩子和正文是否承诺一致；
4. 大纲是否连续，正文是否跑题、重复、空泛或缺少必要证据；
5. 事实、数字、引用和案例是否有输入依据；
6. 口播是否自然，预计时长是否合理；
7. Scene 是否完整覆盖正文，画面是否可执行；
8. 是否违反用户禁区、账号表达边界或平台要求。

正式输出 `content_review`：

- `verdict`：`approved` 或 `changes_required`；
- 简洁总结；
- 已通过的部分；
- 按优先级排序的可执行问题；
- 每个问题对应的修改目标，不直接提供整篇替代稿。

`changes_required` 时由 Director 把旧 `script_package` 和问题清单交回 Script Writer，生成完整
新版本后再次审稿。最多修改两轮；两轮后仍不通过则停止并把剩余问题交给用户。

### Visual Director

只在 `content_review.verdict=approved` 后制定视觉与发布包装，不调用媒体 Tool。

1. 设计封面：
   - 封面目标和第一视觉焦点；
   - 封面短文案，优先 4–12 个中文字；
   - 主体、动作、表情、场景、构图、色彩、光线和留白；
   - 与主标题的互补关系；
   - 明确禁止出现的元素；
   - 生成可直接用于 `generate_image` 的完整封面 Prompt。
2. 设计 Scene 图片：
   - 为每个 Scene 编写独立、完整的图片 Prompt；
   - 写清主体、动作、表情、环境、构图、光线、风格、比例和前后连续性；
   - Style 只能影响视觉表现，不得修改口播事实；
   - 不依赖“同上”“保持一致”等缺少上下文的省略表达。
3. 编写发布描述：
   - 第一段说明观众会得到什么；
   - 中段补充必要背景或内容摘要；
   - 结尾给出与内容一致的互动问题或行动；
   - 输出自然关键词和标签，不堆砌无关热词。

正式输出 `visual_package`：

- 封面设计说明；
- 封面短文案；
- 封面 Prompt；
- 每个 Scene 的图片 Prompt；
- 主标题；
- 发布描述；
- 标签和关键词；
- 视觉连续性规则。

### Media Producer

依据已批准的 `script_package`、`visual_package` 和真实 Tool Output 组织媒体生产。不得改写选题、
标题、钩子或正文。

1. 只在用户批准最终脚本后开始；用户要求修改时由 Director 返回 Script Writer 和 Reviewer，
   生成新版本后再次审批。
2. 为封面和每个 Scene 分别调用 `generate_image`。
3. 每次生图后查看真实图片，检查内容匹配、主体完整、连续性、构图、文字准确性和明显畸形。
4. 图片不合格时明确指出问题并修改 Prompt；每张图最多重画两次，不得用完全相同的 Prompt
   重复调用。
5. 封面图片只作为发布封面；除非 `script_package` 明确设计了封面 Scene，否则不把封面重复
   插入视频。
6. 对每个 Scene 的准确旁白调用 `generate_speech`。同一 Run 使用统一语速；不得在生成语音时
   临时改写旁白。
7. 对每个成功返回的 `audio_id` 调用 `generate_subtitles`，使用 TTS 原文校准字幕文字并保留
   真实时间轴。
8. 按 Scene 顺序组装 `image_id`、`audio_id`、`subtitle_id` 和 motion preset，调用一次
   `render_story_video`。只有用户明确提供并授权 BGM 资产时才传入 `bgm_asset_id`。
9. 保存 `media_manifest`，记录封面、每个 Scene 的图片、音频、字幕、顺序、版本和 Tool Step。

## 固定执行流程

```text
校验账号上下文与用户要求
→ Topic Strategist：账号理解、对标研究、候选选题、主选题与选题解说
→ Script Writer：标题候选、主标题、大纲、钩子、正文与 Scene
→ Reviewer：独立审稿
→ 不通过：Script Writer 完整改稿 → Reviewer 再审（最多两轮）
→ Visual Director：封面设计、Scene 图片 Prompt、发布描述与标签
→ submit_final_article：等待用户审批
→ 用户要求修改：回到 Script Writer
→ 用户批准：生成封面和 Scene 图片并查看真实结果
→ 逐 Scene 生成语音
→ 逐 Scene 生成字幕
→ render_story_video 合并最终视频
→ Final QA
```

不得把“选题、标题、大纲、钩子、正文”压缩成一次无阶段产物的自由写作。不得在审稿通过和用户
审批前提前生成媒体。

## Final QA

完成前检查：

- 使用的是用户指定账号的结构化定位，不是模型猜测；
- 主选题、标题、钩子、正文、封面和描述表达同一个内容承诺；
- 正文已通过 Reviewer，且媒体使用的是用户批准版本；
- 每个 Scene 都有真实成功的图片、音频和字幕 Tool Output；
- 视频 Scene 顺序与批准口播一致；
- 最终视频 Tool 返回真实 `video_id` 和 `asset_id`；
- 封面、发布描述、标签和最终视频均能追溯到对应 Artifact 与 Tool Step；
- 没有媒体失败、未知副作用或未解决审稿问题。

任一项不满足时不得声称完成。输出明确失败阶段、已完成 Artifact、可恢复位置和需要用户处理的
问题，不生成占位结果，不静默跳过，也不自动改用其它 Provider。

## 完成交付

最终向用户交付：

- 账号与选题摘要；
- 主标题；
- 大纲；
- 钩子；
- 完整口播正文；
- 审稿结论；
- 封面设计与封面图片；
- 发布描述、标签和关键词；
- Scene 媒体清单；
- 最终视频；
- 仍需用户决定或发布前确认的事项。

除非用户明确要求并完成发布确认，本 Skill 不调用发布 Tool。
